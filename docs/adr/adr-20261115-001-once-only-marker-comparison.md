# 「1 回だけ書く」印をもう一度書くかは、要件の印の一覧が種類ごとに決めた相手の欄で比べ、署名付きの印を決めた ADR には決定を変えずに読み方を追記する

要件の UNDECIDED-103（「1 回だけ書く」印で、同じ印をもう一度書くかを何で比べるかを、どの決定に置くか。[決めていないこと][undecided]の「ADR で決めること」の「受け入れと印」）を決める。

本 ADR では、要件の「[印と固定の見出しの一覧][f04]」にある「1 回だけ書く」印の箇条（「1 回だけ書く」印（`wait`・`overlap`・`remind`・`ignored-instruction`）は、同じ種類で同じ相手の有効な印があれば書かず、`stop` は止めるたびに書く、と決めた箇条）を「1 回だけ書く決まり」と呼ぶ。

改める決定と、据え置く決定は次のとおり。

## 背景と課題（Context and Problem Statement）

- [ADR-20261015-004][adr-markers] の決定 1 は、進行役の投稿にすべて署名付きの印を付けるとし、印の種類 `note` の欄を、`kind=wait|overlap|remind|stop` と、必要なら `reason=<短い記号>` とした。「1 回だけ書く」は、同じ Issue か PR に、同じ `kind` と `reason` の有効な `note` の印があるかで判定する。手元の記録で判定する案（同じ ADR の案 1-B）は、記録を失うと同じコメントを何度も書くので採らなかった
- [ADR-20261015-006][adr-flow] の決定 4 は、「1 回だけ書く」の判定に手元の記録を使わず、GitHub の状態と印から決めるとした。ADR-20261015-004 で印から判定すると決めたので、手元の記録の用途から外した
- [ADR-20261024-001][adr-model-states] の決定 9 は、印を HTML のコメントの中に 1 行の JSON で書き、種類を `type` の欄に 1 つ持つ形に改めた。`note` と `kind` の 2 段は無くなった。`wait` は `blockedBy`、`overlap` は `prs` と `paths`、`remind` は `head` の欄を持ち、どれも `reason` の欄を持たない（`reason` の欄を持つのは `stop` と `approval-reset`）。
  決定 11 は、`note kind=wait`・`overlap`・`remind`・`link` の印を、`type` が同じ名前の印と読み、決定の中身は変えずに表し方だけを読み替えるとした。`reason` の読み替えは無い
- ADR-20261015-004 のタイトルの下にある、ADR-20261024-001 が改めた旨の注記は、決定 1 の印の書き方を JSON に改めたことと、据え置く決定を並べるが、「1 回だけ書く」の比べ方に触れていない。ADR-20261024-001 の冒頭で ADR-20261015-004 を改めると書いた箇条も同じ
- 今の比べ方は、1 回だけ書く決まりにある。「1 回だけ書く」印は `wait`・`overlap`・`remind`・`ignored-instruction` で、同じ種類で同じ相手（`wait` は `blockedBy` の番号の集合と `hidden` の数の組、`overlap` は `prs`、`remind` は `head`、`ignored-instruction` は `comment`）の有効な印があれば書かない。`stop` は、止めるたびに、止めた先ごとに書く（[04-external-text-and-markers.md][f04]）。
  FLOW-8・FLOW-10（[01-issue-flow.md][f01]）と MERGE-3（[03-merge.md][f03]）は、1 回かどうかを `overlap`・`wait`・`remind` の印で判定するとだけ書く。基本設計の「[状態遷移と判定][design-flow]」にある「ほかの印」の表と、詳細設計の「[印][d-markers]」は、1 回だけ書く決まりと同じ比べ方を書いている
- 比べる欄を ADR の決定として書いたのは、`wait`（[ADR-20261112-001][adr-wait-hidden] の決定 2）と、`ignored-instruction` に書く作業指示のコメントの ID（[ADR-20261024-004][adr-master] の決定 6）だけで、`overlap` の `prs` と `remind` の `head` は要件にだけある。
  ADR-20261112-001 は、冒頭の表で ADR-20261015-004 を据え置くとし、JSON の印に改めた後は要件の印の一覧が種類ごとに比べる欄を決めている、と読んだ
- 比べる細かさは、次のように移ってきた（2026-11-15 に、要件と基本設計の git の履歴で確かめた）
  - ADR-20261015-004 を要件に反映したとき（2026-10-15）、FLOW-10 は、依存で待つ Issue に 1 回だけコメントし、同じ理由で毎回コメントしないとした。印の一覧は、同じ `kind` と `reason` の有効な印があれば書かないとした
  - JSON の印に改める前（2026-10-25 の PR #123 の前）の要件と基本設計は、`wait`・`overlap`・`remind` を同じ `kind` だけで比べた（`reason` を持たないので、Issue か PR ごとに 1 回）。`link` と `duplicate` は番号も、`conflict` は `head` も比べた。種類ごとに比べる欄を足すことは、ADR-20261015-004 の決定 1 を改めずに、要件と設計で行ってきた
  - JSON の印に改めた反映（PR #123）で、要件は `wait` を `blockedBy`、`overlap` を `prs`、`remind` を `head` で比べるとし、同じ Issue か PR でも相手が変われば書くようになった。`wait` は後に、ADR-20261112-001 が `hidden` を足して比べ方を決めた
- 決定 1 の箇条を、決定 11 の読み替え（`kind` を `type` と読む）だけで読むと、`wait`・`overlap`・`remind` には `reason` が無いので種類だけで比べることになり、同じ Issue か PR に 1 回しか書かない。1 回だけ書く決まりと、ADR-20261112-001 の決定 2 と食い違う。どの種類が「1 回だけ書く」印かも、決定 1 の箇条には書いていない
- 印を読む処理（`marker.ts`）と、印を書くかを決める処理（`logic/state/next.ts`）は、導入と点検の実装（段階 3）で作り、まだコードは無い。UNDECIDED-103 は、`marker.ts` を作る前に決めるとした

課題：「1 回だけ書く」印で、同じ印をもう一度書くかを比べる欄を、どの文書のどの決定に置くか。ADR-20261015-004 の決定 1 の箇条を、決定を改めたと扱うか、決定は変わらないと扱うか。

## 判断の決め手（Decision Drivers）

- 読み違えにくさ（確かめやすさ）：ADR-20261015-004 の決定 1 を読んだ人と、印を書くかを決める処理を作る人が、今の比べ方と正本の場所にたどり着ける。決定が変わったかを読み違えない
- 変更のしやすさ：印の欄を変えるときに、比べる欄を直す所が少ない
- 変更の確かめやすさ：比べる欄を変えるときに、メンテナの判断を通ったかを確かめられる。比べる欄が粗くなると、相手が変わっても書かず、人に知らせない。細かくなると、同じ知らせを何度も書く
- 費用：改める承認済みの ADR と、反映の量が少ない
- 制約：承認済みの ADR は、決定を変えるなら新しい ADR、変えないなら注記（追記か訂正の注記）で直す（[ADR の README][adr-readme]）。要件のうち選ぶ判断が要るものは、ADR で決めてから直す（[要件の README][req-readme] の「要件を変えるとき」）。本 ADR は、1 回だけ書く決まりの比べる欄を変えない

## 検討した選択肢（Considered Options）

どの案も、進行 Bot の振る舞い（1 回だけ書く決まりの比べる欄）は今のままである。比べているのは、比べ方の記録の置き場と、ADR-20261015-004 の決定 1 を改めたと扱うかである。

- 案 A：ADR-20261015-004 の決定 1 にある「1 回だけ書く」の箇条に追記を足し、印の書き方を改めた後は、1 回だけ書く決まりで比べると読む。比べる欄の正本は要件に置く（決定は変わらない扱い。UNDECIDED-103 の候補 (A)）
- 案 B：種類ごとに比べる欄を決める ADR を起票し、ADR-20261015-004 の決定 1 の箇条を改める（決定を変える扱い。UNDECIDED-103 の候補 (B)）
- 案 C：ADR-20261024-001 の決定 11 にある読み替えの表に追記を足し、「同じ `kind` と `reason` で比べる」の読み方を書く（決定は変わらない扱い。起票で足した）
- 案 D：ADR には何も足さず、比べ方は要件にだけ置く（今のまま。起票で足した）

## 決定（Decision Outcome）

採用した選択肢:「案 A」。

理由: ADR-20261015-004 の決定 1 が決めた中身（「1 回だけ書く」を、手元の記録でなく、GitHub にある署名付きの有効な印で判定する）は、印の書き方を改めた後も変わらない。古いのは、無くなった `kind` と `reason` の表し方だけなので、決定を改める新しい ADR は要らず、決定 1 の箇条のすぐ後ろに読み方を追記すれば足りる。追記は決定 1 を読む人が必ず通る場所にある。種類ごとの相手の欄は、印の表（種類と欄）と同じ節に置くと、印の欄を変えるたびに 1 か所で直せる。
案 B は、比べる欄が承認済みの ADR の決定になり変更を確かめやすいが、比べる欄を ADR と要件の 2 か所に書き、印の欄を変える ADR が比べ方の ADR も改める。案 C は、読み方を ADR-20261024-001 に置くので、ADR-20261015-004 の決定 1 を読む人がたどり着きにくい。案 D は、正典の ADR が、無い欄で比べると書いたまま残る。

### 決定 1：ADR-20261015-004 の決定 1 にある「1 回だけ書く」の箇条のすぐ後ろに追記を足し、決定は変わらない扱いにする

- 追記には、次の 3 つを書く
  - 印の書き方を JSON に改めた後（[ADR-20261024-001][adr-model-states] の決定 9）は、箇条の「同じ `kind` と `reason` の有効な `note` の印」を、同じ種類（`type`）で、1 回だけ書く決まりが種類ごとに決めた相手の欄が同じ有効な印と読むこと。`reason` は、同じ種類の印を理由ごとに見分ける欄だったので、種類ごとに決めた相手の欄と読む
  - どの種類を「1 回だけ書く」印にするかと、種類ごとに決めた相手の欄の正本は、1 回だけ書く決まりにあること（本 ADR の決定 2）
  - 「1 回だけ書く」を、手元の記録でなく、同じ Issue か PR にある署名付きの有効な印で判定する決定は変わらないこと
- 直し方は、ADR の README にある「決定に関わる新しい事実を書き足す（決定は変わらない）」の追記にし、「訂正の注記」にしない。README の基準（直した後の注記を読んで、決定が変わったと思う人がいるか）で比べると、訂正の注記では思う人が出うるが、追記では出にくいため
  - 訂正の注記は、誤った記述に取り消し線を引く。決定 1 の判定の文に取り消し線があると、読む人は、GitHub の印で判定する決定まで外れたかを疑う。比べる細かさが組み直しの反映で種類だけから相手ごとに変わった（背景）ので、取り消した文と新しい文を比べた人は、決定が変わったと読みうる
  - 追記は、決定したときの文を残し、すぐ後ろで、印の書き方を改めた後の読み方と、判定の決定が変わらないことを書く。`kind` と `reason` の文は、決定したときは誤りでなく、ADR-20261024-001 の決定（印の書き方を改めた）で表し方が古くなった。別の ADR の決定で古くなった本文は、README のとおり本文を残して注記で知らせる（ADR-20261024-001 が足した改めた旨の注記と同じ扱い）
  - 同じ決定 1 には、箇条の読み方を足す追記（2026-11-11）がすでにあり、同じ形にそろう
- 追記の文は、反映の PR で次のとおりに書く（日付は反映の日）

  ```markdown
  > **［<反映の日> 追記］** 印の書き方を JSON に改めた後（[ADR-20261024-001][adr-20261024-001] の決定 9）は、`note`・`kind`・`reason` の欄が無い。上の「1 回だけ書く」の箇条は、同じ Issue か PR に、同じ種類（`type`）で、要件の「[印と固定の見出しの一覧][markers]」にある「1 回だけ書く」印の決まりが種類ごとに決めた相手の欄（`wait` の `blockedBy` と `hidden` など）が同じ有効な印があるかで判定する、と読む。`reason` は、同じ種類の印を理由ごとに見分ける欄だったので、種類ごとに決めた相手の欄と読む。どの種類を「1 回だけ書く」印にするか（`stop` は止めるたびに書く）と、種類ごとに決めた相手の欄の正本は、要件の決まりにある（[ADR-20261115-001][adr-20261115-001]）。「1 回だけ書く」を、手元の記録でなく、同じ Issue か PR にある署名付きの有効な印で判定する決定は変わらない。
  ```

- ADR-20261015-004 のタイトルの下に「Amended by」の注記は足さない（決定を改めないため）。status は `accepted` のまま、`updated` を反映の日にする

### 決定 2：比べる欄の正本は要件の印の一覧に置き、変えるときは ADR で決めてから要件を直す

- どの種類を「1 回だけ書く」印にするかと、種類ごとの相手の欄は、1 回だけ書く決まりを正本にする。印の表（種類と欄）と同じ節に置き、印の欄を変えるときに 1 か所で直す
- 1 回だけ書く決まりの箇条に、ADR-20261015-004 の決定 1 の判定で比べる相手の正本であることを書き、本 ADR へリンクする。比べる欄は変えない
- 比べる欄を変えるときと、「1 回だけ書く」印の種類を足すか外すときは、選ぶ判断が要るので、要件の README にある「要件を変えるとき」のとおり ADR で決めてから要件を直す（ADR-20261112-001 が `wait` に `hidden` を足したときと同じ形）。決める ADR は、ADR-20261015-004 の決定 1 を改めない
- 基本設計の「ほかの印」の表と、詳細設計の「印」は、今のとおり 1 回だけ書く決まりを写す

### 影響（Consequences）

- 良い点（読み違えにくさが上がる）: ADR-20261015-004 の決定 1 を読んだ人が、箇条のすぐ後ろで、JSON の印での比べ方と正本の場所にたどり着ける。決定 11 の読み替えだけで読んで、`wait`・`overlap`・`remind` を種類だけで比べる（同じ Issue か PR に 1 回しか書かない）読み違いを防ぐ
- 良い点（変更のしやすさが上がる）: 比べる欄は、印の欄と同じ節の 1 か所にある。印の欄を変える ADR と要件の直しで済み、比べ方を書き写した ADR を合わせて改めることが無い
- 良い点（費用が下がる）: 承認済みの ADR の決定を改めない。反映は、ADR-20261015-004 への追記 1 つ、1 回だけ書く決まりへの 1 文、UNDECIDED-103 の欠番
- 悪い点（変更の確かめやすさが下がる）: `overlap` の `prs` と `remind` の `head` は、ADR の決定に無いまま残る。比べる欄を変えるときにメンテナの判断を通るかは、要件の README の決まり（選ぶ判断は ADR で決める）と PR のレビューに頼る
- 悪い点（読み違えの残り）: 組み直しの反映（PR #123）で、`wait`・`overlap`・`remind` を比べる細かさが、種類だけ（Issue か PR ごとに 1 回）から相手ごとに変わった。本 ADR は細かさの変化を、決定 1 の `reason`（同じ理由で毎回書かない）の読み方として扱い、決定の変更と扱わない。字面の `reason` を細かさの決定と読む人には、決定が変わったと見えうる
- 中立: 進行 Bot の振る舞いは変わらない（1 回だけ書く決まりの中身は今のまま）。どの案も同じ

### 確認方法（Confirmation）

- 反映の PR のレビューで、次を確かめる
  - ADR-20261015-004 の決定 1 にある「1 回だけ書く」の箇条のすぐ後ろに、決定 1 で示した文の追記があり、箇条に取り消し線を引いていないこと
  - 1 回だけ書く決まりの箇条に、比べる相手の正本であることと、本 ADR へのリンクがあり、比べる欄が変わっていないこと
  - `docs/` を「`` `kind` と `reason` ``」で検索し、ADR-20261015-004 の決定 1 の箇条と追記、UNDECIDED-103 の欠番の文、本 ADR、ADR-20261112-001 の冒頭の表のほかに、比べ方の根拠として `kind` と `reason` を引く所が無いこと
- 単体テスト（`logic/state/next.ts`）で、1 回だけ書く決まりの種類ごとに、同じ種類で相手の欄が同じ有効な印があれば書かず、相手の欄が違えば書くことを確かめる。`stop` は、同じ `reason` の有効な印があっても、止めるたびに書くことを確かめる

## 選択肢ごとの長所と短所（Pros and Cons of the Options）

### 案 A：ADR-20261015-004 の決定 1 の箇条に追記を足し、比べる欄の正本は要件に置く

- 良い点（読み違えにくさが上がる）: 追記は決定 1 の箇条のすぐ後ろにあり、決定 1 を読む人が必ず通る。案 B もタイトルの下の注記で届くが、案 C は ADR-20261024-001 の決定 11 までたどらないと見えず、案 D は読み方がどこにも無い
- 良い点（変更のしやすさが上がる）: 案 B と違い、比べる欄は印の表と同じ節の 1 か所にだけ書く（案 C・D も同じ）。読む人に届くことと、1 か所にだけ書くことを両方満たすのは案 A だけ
- 良い点（費用が下がる）: 案 B と違い、新しい ADR に比べる欄を書き写さず、ADR-20261015-004 に「Amended by」を足さない（案 C はほぼ同じ。案 D はもっと少ない）
- 悪い点（変更の確かめやすさが下がる）: `overlap` と `remind` の比べる欄は、ADR の決定に無いまま。変えるときにメンテナの判断を通るかは、要件の README の決まりに頼る（案 B は承認済みの ADR の決定が守る）
- 悪い点（読み違えの残り）: 組み直しで比べる細かさが変わったことを、決定 1 の読み方として扱う。字面の `reason` を細かさの決定と読む人には、決定が変わったと見えうる（案 B は決定の変更として記録する）

### 案 B：種類ごとに比べる欄を決める ADR を起票し、ADR-20261015-004 の決定 1 の箇条を改める

- 良い点（変更の確かめやすさが上がる）: 種類ごとの比べる欄が承認済みの ADR の決定になり、変えるには新しい ADR が要る。`overlap` の `prs` と `remind` の `head` も ADR の決定に載る
- 良い点（読み違えにくさが上がる）: 組み直しで比べる細かさが変わったことを、決定の変更として記録でき、字面の `reason` を細かさの決定と読む人も迷わない
- 悪い点（変更のしやすさが下がる）: 比べる欄が、新しい ADR と要件の 2 か所に書かれる。印の欄を変える ADR（ADR-20261112-001 が `wait` に `hidden` を足したような ADR）は、比べ方の ADR も改め、「Amended by」が重なる
- 悪い点（費用が上がる）: 新しい ADR に今の比べる欄を書き写し、ADR-20261112-001 の決定 2 と ADR-20261024-004 の決定 6 が決めた欄と重ねて書く。ADR-20261015-004 に「Amended by」を足す

### 案 C：ADR-20261024-001 の決定 11 にある読み替えの表に追記を足す

- 良い点（読み違えにくさが上がる。ADR-20261024-001 を読む人に）: 組み直す前の書き方の読み替えが、決定 11 の 1 つの表にそろう
- 中立: 決定を改めず、費用は案 A とほぼ同じ
- 悪い点（読み違えにくさが下がる）: ADR-20261015-004 の決定 1 を読む人は、タイトルの下にある ADR-20261024-001 の改めた旨の注記（比べ方に触れていない）から決定 11 までたどらないと、読み方に着かない。UNDECIDED-103 が見つけた隙間が、ADR-20261015-004 の側に残る
- 悪い点: 決定 11 は、組み直す前の表し方を、組み直した後の表し方へ 1 対 1 で読み替える表である。`reason` は、種類ごとに違う欄（`blockedBy`・`prs`・`head`・`comment`）に当たり、1 対 1 の読み替えにならない

### 案 D：ADR には何も足さず、比べ方は要件にだけ置く

- 良い点（費用が最も少ない）: ADR を直さない。得るものは費用の少なさだけ
- 悪い点（読み違えにくさが下がる）: 正典の ADR-20261015-004 の決定 1 は、無くなった `kind` と `reason` で比べると書いたまま残る。決定 11 の読み替えだけで読むと、`wait`・`overlap`・`remind` を種類だけで比べ、1 回だけ書く決まりと ADR-20261112-001 の決定 2 と食い違う。印を読む処理（`marker.ts`）を作る前に解くとした UNDECIDED-103 が、解けないまま残る
- 悪い点（変更の確かめやすさが下がる）: 比べる欄の正本が要件にあることと、変えるときの決め方が、どの決定にも書かれない
