# 片付けと戻した後に作業場所を消す前は残りのプロセスを探し、見つかれば消さずに止める

要件の UNDECIDED-88（AI のセッションの残りを止められずに停止中（`session-not-stopped`）にした作業の単位を、人がマージしたか閉じたときに、片付けで作業場所を消してよいか。[決めていないこと][undecided]の「ADR で決めること」の「作業の単位の状態遷移」）を決める。
本 ADR は、[ADR-20261024-006][adr-cleanup]（マージと中止の後は片付けの前の状態を挟んで進行 Bot が片付ける）と、[ADR-20261025-001][adr-tampered]（片付けをやり直さない条件を、マージ済みか閉鎖済みに入った後の `stop` の印で決める）を前提にする。

改める決定と、据え置く決定は次のとおり。

| ADR | 扱い | 改める決定 | 据え置く決定 |
| --- | --- | --- | --- |
| [ADR-20261024-006][adr-cleanup]（マージと中止の後の片付け、先の依頼、載せ直し） | 一部を改める | 決定 1 の「作業場所を消す前の確かめ」に、残りのプロセスの確かめを足す（本 ADR の決定 1・2） | 決定 1 のほかの項目（片付けは軸の値と全体の停止を問わず行う、軸の値を書き換えない、作業場所が作ったときと違えば消さずに止める、片付けが失敗し続けたら `cleanup-failed` で止める）。決定 2〜4 |
| [ADR-20261025-001][adr-tampered]（片付けの中の作業場所の確かめ） | 据え置く | — | 決定 2（マージ済みか閉鎖済みに入った後に停止中にしたら、人が再開するまで片付けをやり直さない）。本 ADR で片付けの中で止めたときも、決定 2 に当たる |
| [ADR-20261018-001][adr-usage]（セッションの止め方と費用の数え方） | 据え置く | — | 決定 1 の「残りが止まったと確かめられなければ、作業場所を消さない」。本 ADR は、同じ考えを片付けと戻した後に作業場所を消すときにも当てる |

## 背景と課題（Context and Problem Statement）

- AI のセッションを止めた後や、前の実行が残したセッションを探したときに、残りのコマンドが止まったと確かめられなければ、作業場所を消さずに停止中（`session-not-stopped`。実装の都合の記号）にする（[ADR-20261018-001][adr-usage] の決定 1、IMPL-14、基本設計の「[AI のセッション][design-ai]」の「止める手順」と「前の実行が残したセッション」）。人に渡したセッションの残りは、次の実行で止め直さない
- 片付け（T27・T28）は、軸の値と全体の停止を問わず行う（[ADR-20261024-006][adr-cleanup] の決定 1）。片付けをやり直さないのは、マージ済みか閉鎖済みに入った後に停止中にしたときだけ（[ADR-20261025-001][adr-tampered] の決定 2）
- `session-not-stopped` で止めた後に、人が PR をマージするか、push 以上の人が Issue を閉じると、最新の `stop` の印はマージか閉じた時刻より前なので、片付けは止まらない。片付けは、残ったコマンドがあるまま作業場所を消しうる（2026-10-25 に、ADR-20261025-001 の起票のときに見つけた）
- 戻した後（`## 再開 計画から`・`下書きから`）に前の PR のフォルダを消すとき（基本設計の「[状態遷移と判定][design-flow]」の「先に見る」の順 9）も、同じく残りを探さずに消す
- 同じ名前のフォルダを作り直す前には、もう残りを探している（作業フォルダかファイルを開いているプロセスを `lsof` と `lsof +D` で探す。基本設計の「[AI のセッション][design-ai]」の「止める手順」の表の下）

課題：進行 Bot が作業場所（セッションのフォルダと短い一時フォルダ）を消す前に、残ったプロセスをどう確かめ、見つかったらどうするか。

## 判断の決め手（Decision Drivers）

- 残ったコマンドがあるまま、作業場所を消さない（止める側に倒す）
- 止めた理由の記号や、止めた時刻に依らず、消す直前の事実で決める
- 手元の記録を判定に使わない（[ADR-20261015-006][adr-flow] の決定 4）
- 進行 Bot が作業場所を消すどの場面（作り直す直前・片付け・戻した後）でも、同じ確かめ方にする
- 人に渡したプロセスを、進行 Bot が黙って止めない

## 検討した選択肢（Considered Options）

- 案 A：最新の `stop` の印の記号が `session-not-stopped` なら、時刻を問わず、人が再開するまで片付けない
- 案 B：作業場所を消す前に、作り直す前と同じ探し方で残りのプロセスを探し、見つかれば消さずに停止中にする
- 案 C：今のまま片付ける（人が残りを止めてから、マージするか閉じる）
- 案 D：手元の記録（セッションの終わりの行に、`session-not-stopped` で人に渡したと書いたか）を見て、人に渡したセッションの作業場所を消さない

## 決定（Decision Outcome）

採用した選択肢:「案 B」。

理由: 消す直前に残りを探すので、止めた理由の記号や時刻、手元の記録に依らずに、残ったコマンドがあるまま消すことを防げる。`session-not-stopped` で止めていない作業の単位に残ったプロセスも守れる。作り直す前にもう行っている確かめを、片付けと戻した後にも当てるだけで、作業場所を消すどの場面でも同じ確かめ方になる。

### 決定 1：作業場所を消す前に、残りのプロセスを探す

- 進行 Bot は、片付け（T27・T28）と、戻した後に前の PR のフォルダを消すとき（先に見るの順 9）に、セッションのフォルダと短い一時フォルダを消す前に、残りのプロセスを探す。探し方は、作り直す前と同じ（作業フォルダがフォルダの中にあるか、フォルダの中のファイルを開いているプロセス。`lsof` と `lsof +D`）
- 探すのは、その場面で消すフォルダの組のすべて（片付けなら、名前から作業の単位を引けるフォルダのすべて）
- 作業場所が作ったときと同じかの確かめ（[ADR-20261013-001][adr-workspace]）と、残りのプロセスの確かめの、両方に通ったフォルダだけを消す

### 決定 2：見つかるか、探し切れなければ、消さずに止める

- プロセスが見つかるか、探し方が時間の上限（`run.commandMinutes`）を超えるか失敗して探し切れなければ、フォルダを消さずに停止中（`session-not-stopped`）にする。片付けの中なら、片付けの前の状態（マージ済みか閉鎖済み）のまま止める
- 止めた理由のコメントに、見つかったプロセスの PID とコマンドの名前と、消すフォルダの組（セッションの名前と短い一時フォルダの ID。絶対パスは GitHub に書かない）を書く。人は、残りを止めてから `## 再開 続きから` を書く
- 進行 Bot は、見つかったプロセスを止めない。人に渡したセッションの残りか、止めてよい相手（基本設計の「止める相手」）と確かめられないプロセスなので、止めると人が調べる材料を失いうる
- 片付けの失敗の続いた回数には数えない。片付けの中で止めたときは、マージ済みか閉鎖済みに入った後の停止中なので、[ADR-20261025-001][adr-tampered] の決定 2 で、人が再開するまで片付けをやり直さない。順 9 で止めたときは、止め方に値があるので、人が再開するまで順 9 も動かない

### 影響（Consequences）

- 良い点: `session-not-stopped` で止めた後に人がマージしても、残ったコマンドがあるまま作業場所を消さない
- 良い点: 止めた理由の記号・時刻・手元の記録に依らず、消す直前の事実で決まる
- 良い点: 作業場所を消すどの場面でも、同じ確かめ方になる
- 悪い点: 片付けのたびに `lsof` と `lsof +D` を回すので、片付けに時間がかかる（大きな依存のフォルダがあると長い）。時間の上限を超えたら、消さずに止める
- 悪い点: 人が調べるためにフォルダを開いたまま（エディタや端末）だと、片付けが止まる。人は閉じてから `## 再開 続きから` を書く
- 中立: 1 秒の間に生まれて作業フォルダを外に移し、ファイルも開いていないコマンドは、今の探し方と同じく見つからない（基本設計の「止める手順」の表の下、FACT-38）

### 確認方法（Confirmation）

- 結合テストで、作業場所のフォルダを作業フォルダにしたプロセスを残したまま PR をマージすると、片付けがフォルダを消さずに `session-not-stopped` で止まり、`stop` の印が 1 つだけ書かれ、次の実行で片付けをやり直さず、プロセスを止めて `## 再開 続きから` を書いた後の実行で片付けが終わる（`cleanup` の印）ことを確かめる
- 結合テストで、`session-not-stopped` で止めた後（残りはまだある）に人が PR をマージした筋書きで、片付けが消さずに止まることを確かめる
- 結合テストで、戻した後の順 9 で、前の PR のフォルダに残りのプロセスがあると、消さずに止まることを確かめる
- 単体テストで、探し方が時間の上限を超えたか失敗したときに、消さずに止める判定になることを確かめる

## 選択肢ごとの長所と短所（Pros and Cons of the Options）

### 案 A：最新の stop の印の記号が session-not-stopped なら片付けない

- 良い点: 探す手間が要らず、片付けが速い
- 悪い点: 止めた理由の記号で決めるので、[ADR-20261025-001][adr-tampered] が記号に依らない形にした考えとずれる
- 悪い点: `session-not-stopped` の後に別の理由で止めて再開すると、最新の `stop` の印が変わり、守れなくなる。記号に当たらない残り（止めたと確かめた後に残ったもの）は守れない

### 案 B：消す前に残りのプロセスを探し、見つかれば止める

- 良い点: 消す直前の事実で決まり、記号・時刻・手元の記録に依らない
- 良い点: 作り直す前の確かめと同じ形で、作業場所を消すどの場面でも同じになる
- 悪い点: 片付けに時間がかかる

### 案 C：今のまま片付ける

- 良い点: 決まりを足さずに済む
- 悪い点: 人が残りを止め忘れてマージすると、残ったコマンドがあるまま作業場所を消す。人の記憶に頼るので、止める側に倒れない

### 案 D：手元の記録で、人に渡したセッションの作業場所を消さない

- 良い点: 探す手間が要らない
- 悪い点: 手元の記録を判定に使うことになり、[ADR-20261015-006][adr-flow] の決定 4（手元の記録は実行をまたぐ上限の数え上げにだけ使う）に反する。記録を失うと、守れなくなる
