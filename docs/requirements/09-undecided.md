# 決めていないこと

要件の中で、まだ決めていないことの一覧。決め方で 3 つに分ける。

- ADR で決めること：要件の中で答えが食い違っているか、答えが無い論点。どちらにするかを選ぶ判断なので、ADR を起票して決め、決まったら関係する要件のファイルを直す
- 基本設計の中で決めてよいもの：要件の形を変えない細かい選択
- 確かめること：判断ではなく、事実を確かめれば済むもの

  一方、「[止まった状態から戻す手順][f01]」の `unlinked-pr` と `pr-closed` の項目と、基本設計の「[状態遷移と判定][design-flow]」の次の工程の表の順 4（閉じた PR と、結びつきの印の無い PR）は、人が戻した時刻より前に閉じた PR（結びつきの印の無い PR を含む）を、Status を問わず、着手の後も外し続ける形で結びつきから外し、計画からやり直す。閉じた PR を外す形を前提にした [ADR-20261021-003][adr-reapprove] の決定 2（承認のやり直し）と [ADR-20261021-004][adr-marker-keys] の決定 5（無効な印からの戻し方）も、改める決定に [ADR-20261016-001][adr-pr] を挙げていない。[ADR-20261016-001][adr-pr] と IMPL-6 のとおりに作ると、人が PR を閉じて戻した Issue が、閉じた PR のために止まり続ける。
  また、戻す手順で `needs-human` を外す位置が 2 通りある。「止まった状態から戻す手順」の最初の項目と [ADR-20261021-004][adr-marker-keys] の決定 5 は、最後に外す。承認のやり直し（[ADR-20261021-003][adr-reapprove] の決定 2）、`unlinked-pr`、受け入れの検疫で止まったときの人への案内（TEXT-12）と、要件の図「Issue の流れ」は、先に外す。承認のやり直しで先に外すと、`agent-ready` を付け直す前に入った実行が、PR があれば `pr-closed`、PR が無ければ `brief-changed` で止まり直す。`needs-human` の無い Issue の承認のやり直しにも、人の操作の途中に実行が入る間がある（基本設計の 4 回目の再レビューで見つけた。2026-10-22）。
  決めること：閉じた PR を結びつきから外す例外を、[ADR-20261016-001][adr-pr] の決定 3 に足すか。足すなら、条件（人が戻した時刻の決め方、Status を問わないこと、着手の後も外し続けること）。戻す手順で `needs-human` を外す位置と、`needs-human` の無い Issue の承認のやり直しで、途中の実行に触らせない手段。
  候補（閉じた PR の例外）：(C1) 新しい ADR で、[ADR-20261016-001][adr-pr] の決定 3 に例外を足し、IMPL-6 にも書く。マージされずに閉じた PR（結びつきの印の無い PR を含む）が、人が戻した時刻より前に閉じられていれば、Status を問わず、止めずに結びつきから外し、ほかに結びつく PR が無ければ計画からやり直す。人が戻した時刻は、push 以上の人が最後に `needs-human` を外した時刻、最新の `intake-final` の印の時刻、承認のやり直しに当たる `agent-ready` を付けた時刻（新しい `intake-final` の印を書くまで）のうち、最も遅いもの。人が戻した時刻より後に閉じた PR は、今のとおり `pr-closed` で止める。(C2) [ADR-20261021-003][adr-reapprove] の決定 2 と [ADR-20261021-004][adr-marker-keys] の決定 5 が決定 3 を改めたと読み、2 本と [ADR-20261016-001][adr-pr] に訂正の注記を足す（「Status を問わず」「着手の後も外し続ける」は 2 本の決定に無いので、注記では覆えない）。(C3) 例外を外し、閉じた PR はいつも `needs-human` にする（人が PR を閉じて戻す手順が止まり続け、2 本の ADR と食い違う）。
  候補（`needs-human` を外す位置）：(i) どの戻す手順も、`needs-human` が付いた状態で行い、最後に外す。`needs-human` の無い Issue で承認をやり直すときは、人が最初に `needs-human` を付ける。(ii) `needs-human` のある Issue は (i) と同じにし、`needs-human` の無い Issue では、最初に Agent 欄を `paused` にし、最後に戻す（FLOW-32 の一時停止）。(iii) 順を変えず、最後に外す決まりを外し、承認のやり直しでは PR を閉じてから `needs-human` を外すことを書き添える。
  推奨は (C1) と (i)。例外を承認済みの ADR の決定に置き、[ADR-20261021-003][adr-reapprove] と [ADR-20261021-004][adr-marker-keys] が前提にした形を追認する。人が戻した時刻より後に閉じた PR は今のとおり止まり、人が閉じた意図を確かめる決定 3 の目的を保つ。`needs-human` があれば進行 Bot は Issue に触らないので、人の操作の途中に実行が入っても止まり直さず、戻す手順が 1 通りになる。[ADR-20261021-003][adr-reapprove] の決定 2 の順（`needs-human` を先に外す）は改める。計画・実装工程（段階 5。PR を作り始める段階）の前に決める（[02-implement-review-fix.md][f02]、[01-issue-flow.md][f01]、[04-external-text-and-markers.md][f04]）~~
