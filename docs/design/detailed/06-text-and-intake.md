# 文の検査と受け入れ

AI に渡す文と GitHub に書く文を扱う処理（検疫、漏えいの検査、ハッシュ、コメントの組み立て、出力契約の取り出し、見出しの比べ方）と、人が呼ぶ intake の Skill の処理を決める。
検疫を掛ける文と時は要件の [TEXT-11][text]、漏えいの検査を掛ける文は [IMPL-15][impl]、URL の照らし方・出力契約の欄・コメントの形・ハッシュの取り方・intake の流れは基本設計の「[AI のセッション][b03]」が正本。本書は、正本が種類だけを挙げた検査の中身と、処理の作りを決める。

## 検疫

### 結果の形

検疫は、見つかったものの並び（空なら通った）を返す。1 件は、種類の記号と、場所を持ち、見つかった文の中身を持たない（[TEXT-11][text]、「[AI のセッション][b03]」の「人の Skill から受け入れを呼ぶ形」）。

| 種類の記号 | 検査 |
| --- | --- |
| `delimiter` | 欄の区切りと、印と指摘の区切りの行を模した文字列 |
| `instruction` | 指示の形の語 |
| `invisible` | 見えない文字 |
| `html-comment` | HTML のコメント |
| `encoded` | 長い base64・16 進と、符号を並べた難読化 |
| `url` | 当てる先のリポの GitHub の URL のほかの URL |
| `attachment-url` | GitHub の Issue の添付の URL（`url` と分けて数える。「[AI のセッション][b03]」の「検疫が探す URL」） |

- 場所は、文の種類（題名・本文・何番目のコメント・欄の名前）と、PR の差分ならファイルのパスと新しい側の行の番号
- 種類の記号は、`security` の印の `finding` の値の一覧でもある（「[印][d03]」の「欄の値の形」が本節に任せた）。見つかった種類が 2 つ以上あるときは、表の上の行ほど先にして 1 つを `finding` に書き、攻撃の疑いのコメントの本文には、すべての種類と場所を書く
- 漏えいの検査の種類（下の「漏えいの検査」）も、`security` の印の `where` が `leak` のときの `finding` の値にする

### 検査ごとの決まり

どの検査も、書いてあるままの文と、正規化した文（見えない文字を除き、Unicode の互換の正規化（NFKC）をした文）の両方で探す。見えない文字や全角の文字で崩した形を見逃さないため（URL の検査の崩した形の決まりと同じ考え方）。

| 種類 | 探すもの |
| --- | --- |
| `delimiter` | (1) 役ごとの入力の欄の区切りの、決まった前と後の文字列（`logic/session/` の定数。乱数の部分を問わず、決まった部分が現れたら当たる。「[AI のセッション][b03]」の「渡し方の決まり」）。(2) 印の形と、指摘の区切りの行の形（「[印][d03]」の「印の形の見つけ方」と同じ見つけ方）。英字の大小は区別しない |
| `instruction` | `logic/text/patterns.ts` の指示の形の語の一覧（英語と日本語。例：前の指示を無視させる言い方、役を名乗る行の始まり（`system:`、`assistant:`）、役を表すタグ（`<system>`、`[INST]`、`<\|im_start\|>`）、システムの指示を名指す語）。空白の続きを 1 つにし、英字の大小を区別せずに照らす |
| `invisible` | 制御文字（タブ・改行・復帰のほか）、Unicode の書式の文字（ゼロ幅の文字、向きを変える文字、タグの文字 U+E0000〜E007F、ソフトハイフンなど。一般の分類が Cf のもの）、行と段落の区切り（U+2028・U+2029）、ハングルの埋め字（U+115F・U+1160・U+3164・U+FFA0）、異体字の選択子（U+FE00〜FE0D と U+E0100〜E01EF） |
| `html-comment` | コードの書式の外の `<!--`。コードの書式の中は、人の目にも文字として見えるので探さない。コードの書式かは、URL の検査と同じ `logic/text/markdown-code.ts` で決める |
| `encoded` | base64 の文字（英数字と `+`・`/`・`-`・`_`。末尾の `=` を含む）が切れ目なく 100 文字以上続き、英字と数字の両方を含むもの。16 進の文字が 100 文字以上続くもの。`%XX`・`\xXX`・`\uXXXX`・`&#…;` の符号が 10 個以上続くもの |
| `url` と `attachment-url` | 「[AI のセッション][b03]」の「検疫が探す URL」のとおり |

- `invisible` は、ゼロ幅の結合子（U+200D）と異体字の選択子の U+FE0E・U+FE0F だけ、絵文字の並びの中（前後が絵文字（Unicode の `Extended_Pictographic`）の文字）では当てない。絵文字を使った人の文で毎回止めないため。ほかの所の U+200D は当てる
- `encoded` の 100 文字は、パッケージのロックファイルの完全性のハッシュ（`sha512-` に続く base64 の 88 文字）を当てず、隠した文を入れられる長さの塊を当てる境目として決めた。100 文字に満たない base64 でも、文を隠すことはできる。検疫は網であって壁でない（[TEXT-11][text]）ので、短い塊は AI の権限の制限で受ける
- 指示の形の語の一覧は、言い換えを取りこぼす前提の網で、新しい手口を見つけたら一覧と `fixtures/quarantine/` の見本に足す（[TEXT-11][text]）。一覧に足すのは、検疫を強める向きなので ADR は要らない。一覧から外すのは、範囲を狭める変更なので PR の本文に理由を書く

### 掛ける文

検疫を掛ける文と時は [TEXT-11][text] の表のとおり。本書は、PR の差分の範囲だけを決める。

- PR の差分は、足した行（diff の `+` の行）だけを検疫する。消した行と前後の行は base ブランチの中身で、base ブランチのファイルは検疫しない（[TEXT-11][text]）。場所は、ファイルのパスと新しい側の行の番号で書く
- 中身を文で持たないファイル（git が binary とみなすもの）は、diff に中身が出ないので検疫しない。AI にも中身を渡さない

## 漏えいの検査

`logic/text/leak.ts` は、GitHub に書くすべての文（[IMPL-15][impl] の一覧。diff は足した行）を検査し、見つかったものの並びを返す。結果の形は検疫と同じ（種類の記号と場所。見つかった文の中身は持たない）。

| 種類の記号 | 探すもの |
| --- | --- |
| `secret-format` | 鍵とトークンの決まった形（`logic/text/patterns.ts` の一覧。例：PEM と OpenSSH の秘密鍵の始まりの行、GitHub のトークン（`ghp_`・`gho_`・`ghu_`・`ghs_`・`ghr_`・`github_pat_`）、主なクラウドとサービスのキーの形）。あわせて、進行 Bot が秘密の置き場から読んだ値の、書いてあるままの文字（印の署名の鍵の各行、Webhook の URL、秘密鍵のファイルの各行のうち 32 文字以上のもの）が文の中にあるか |
| `email` | メールアドレスの形。例のために予約されたドメイン（`example.com`・`example.org`・`example.net`・`.example`・`.invalid`・`.test`）、GitHub の `users.noreply.github.com`、進行 Bot の commit の作者のアドレス、`git@<ホスト>` は当てない |
| `machine-path` | マシンの実体のパス：ホームのフォルダ、マシンの設定の `paths.*` と `sessionTmp.root` と `devAutopilotPath`、マシンの設定のフォルダ、macOS の人の一時フォルダ（`getconf DARWIN_USER_TEMP_DIR`）。照らす値は、呼ぶ側が実体のパスに解いて渡す |
| `bot-record` | 手元の記録の識別子の形（実行 ID と依頼の ID の `YYYYMMDDTHHMMSSZ-<16 進の 4 文字>`。「[設定と記録][d02]」の「実行 ID と依頼の ID」）と、セッションの名前と短い一時フォルダの ID の形（「[AI のセッション][b03]」の「セッションの名前」「短い一時フォルダ」） |

- 進行 Bot が読んだ秘密の値と照らすときも、値は秘密の値の型（「[外との境][d01]」の「秘密の置き場」）のまま渡し、見つかったときの結果に値を入れない
- 進行 Bot が自分で組み立てる決まった文（印、決まった見出し、固定の文）は検査しない。AI の文と、人の文を写したもの（マスターに写した作業指示など）と、diff と commit を検査する

## 検査を通った文の型

`logic/text/checked.ts` に、検疫と漏えいの検査の両方を通った文だけが持てる型（`CheckedText`）を置く。

- `CheckedText` を作れるのは、検疫と漏えいの検査を掛けて、どちらも何も見つからなかったときに値を返す 1 つの関数だけにする。型は、TypeScript の名目の型（ほかの文字列から作れない形）にする
- コメントを組み立てる関数（`logic/text/comments.ts`）と、AI に渡す欄を組み立てる関数（`logic/session/`）は、AI の文と人の文を `CheckedText` でだけ受け取る。検査を通していない文をコメントや欄に入れる書き方を、型の検査で止めるため（人の注意でなく仕組みで守る）
- 印の形と指摘の区切りの行の形を取り除く処理（「[印][d03]」の「AI の文から印の形を取り除く」）は、検査の前に掛ける。取り除いた後の文を検査し、通ったものを `CheckedText` にする

## ハッシュ

`logic/text/hash.ts` は、「[AI のセッション][b03]」の「ハッシュの取り方」のとおりに、正規化と SHA-256 を行う。

- 正規化は、CR と CRLF を LF にし、行ごとに末尾の空白（空白・タブ）を除き、前と後ろの空の行を除く。Unicode の正規化はしない。見た目が同じでも文字が違えば、違う文として扱うため
- Issue の文のハッシュは、題名・本文・コメントの本文（作成の順）を 1 つずつ正規化し、改行・NUL 文字・改行の 3 文字でつないでから取る

## コメントの組み立て

`logic/text/comments.ts` に、決まった見出しと固定の文を、言語（リポの設定の `conventions.language`）ごとの表で持つ。今の表は `ja` だけで、ほかの言語は固定の文を足すときに表に足す。表に無い言語ではコメントを組み立てられないので、点検の設定の組で fail にする（「[設定][b01]」の `conventions.language` の形を、表にある言語に限った）。

- コメントは、決まった部分（見出し、「AI が生成した」の 1 行、固定の文）と、`CheckedText` の文と、最後の印の行（`marker.ts` で組み立てたもの）をつないで作る
- 組み立てたコメントが 60,000 文字を超えたときの扱いは、「[AI のセッション][b03]」の「共通の決まり」と「レビューのコメントの形」のとおり。長さは、JavaScript の文字列の長さでなく Unicode の文字の数で数える（GitHub の上限が文字の数のため）

## 指摘の区切りの行と見出しの比べ方

`logic/text/findings.ts` は、指摘の区切りの行（`<!-- dap-finding … -->` と `<!-- dap-finding-end -->`。形は「[AI のセッション][b03]」の「レビューのコメントの形」）を組み立てて読み、指摘の ID を計算する。

- 見出しの正規化は、[ADR-20261019-001][adr-repeat] の決定 1 のとおり（NFKC、先頭の重要度の記号（🔴 🟡 🟢）と空白を除く、英字を小文字にする）。指摘の ID の計算と、🟢 を記録する Issue の題名の比べ方（「[状態遷移と判定][b02]」の「状態ごとの工程」のレビュー合格の (1)）は、同じ正規化の関数を使う。正規化した題名と正規化した見出しが同じなら、同じ見出しとする
- 区切りの行の欄は `<名前>=<値>` を空白 1 つで並べ、値の見出しとパスは `encodeURIComponent` の符号で書く（「[AI のセッション][b03]」の「レビューのコメントの形」）。読むときは、欄の名前の並びと値の形（ID は 16 進の 8 文字、確信度は 0〜100 の整数など）を確かめ、外れた行のあるコメントは読めないものとして扱う
- 基本設計の「レビューのコメントの形」に残っていた「`dev-autopilot:` で始めない」は、印の行の形（`<!-- dev-autopilot {…} -->`。「[印][d03]」の「書く形」）に合わせて直した

## 出力契約

`logic/text/contracts.ts` に、役と工程ごとの出力契約のスキーマを、表で 1 か所に持つ（「[AI のセッション][b03]」の「役ごとの出力契約」の表を写す）。

- スキーマの表は、キー、型（文・文（1 行）・文の一覧・真偽・数・決まった値）、必ずあるか、長さの上限（1 行の欄は 200 文字、ほかの文の欄は 2,000 文字、文の一覧は 20 件まで。`plan.paths` は 200 件まで）を持つ。設定の表（「[設定と記録][d02]」の「設定の表を 1 か所に持つ」）と同じ書き方にし、同じ確かめの関数を使う。JSON スキーマのライブラリは使わない（「[導入と点検][b04]」の「依存」）
- 取り出し：`stream-json` の最後の `result` の行の `result` の文を、前後の空白を除いて読む。全体が 1 つのコードブロック（最初の行が `` ```json ``、最後の行が `` ``` ``）なら、区切りの行を外す。残りを JSON として解き、オブジェクトでなければ取り出せないとする
- 確かめ：表に無いキー、必ずある欄の欠け、型の違い、決まった値のほかの値、長さの上限を超えた欄を、問題の並びにして返す。問題が 1 つでもあれば、実行の失敗にする（「[AI のセッション][b03]」の「共通の決まり」）。問題には、キーの名前と問題の種類だけを書き、AI の文を写さない
- 拒否で止まったとき（`stop_reason` が `refusal`）は、取り出しの前に分ける（「[AI のセッション][b03]」の「役ごとの出力契約」の受付 AI）。`environmentError` を返したときの扱いも、取り出しの後の確かめで分ける（「[AI のセッション][b03]」の「共通の決まり」）
- 確かめを通った値の文の欄は、まだ AI の文なので `CheckedText` でない。GitHub に書く前と次の AI に渡す前に、検疫と漏えいの検査を通す

## 人が呼ぶ intake

![intake の 2 つの引数][fig-intake]

`flow/skill/intake.ts` は、「[AI のセッション][b03]」の「人の Skill から受け入れを呼ぶ形」の順 1・3・8 を受け持つ。lock を取らず、`claude` を起こさず、秘密を読まず、手元の記録に書かない（[README][readme] の「入口ごとの import の範囲」）。

| 引数 | すること |
| --- | --- |
| 検疫 | 標準入力で受けた Issue の文（題名・本文・コメントの本文の並び。JSON）を、`logic/text/quarantine.ts` に通し、結果（無し、または見つかった種類と場所）を JSON で返す。当てる先のリポの owner と名前は、マシンの設定から読む。GitHub を読まない（Issue の文は、呼ぶ側の `/verify-issue` が読んで渡す） |
| 下書き | lock と、待つ時間の内の受け入れの依頼を見て、置けるときだけ、受け入れの依頼を置くコマンドの文（書く先のパスと中身）を返す。Skill が人の許可を得て sandbox の外で動かし、ジョブを起こす。結果のファイルを待ち、受け取ったら下書きか理由を示して、結果を消すコマンドの文を返す（`check` と同じ。「[点検][d04]」の「人が呼ぶ check」） |

- 引数「検疫」は、入力の形（題名・本文・コメントの並び）が違えば、検疫をせずに形が違うことを返す。通ったと返さない
- 引数「下書き」の結果のファイルの形は、「[設定と記録][d02]」の「依頼と結果のファイル」の `intake-result-<依頼の ID>.json` に、受付 AI の文の欄（`CheckedText` を通ったもの）か起こさなかった理由と、費用を入れる

## テスト

| ファイル | 単体テストで確かめること |
| --- | --- |
| `logic/text/quarantine.ts`・`urls.ts` | `fixtures/quarantine/` の見本のすべて（見つけるべき文と、見つけてはいけない文）。崩した形（見えない文字、全角、`%` の符号）でも見つけること。見つかった種類の並べ方と、結果に文の中身が入らないこと |
| `logic/text/markdown-code.ts` | GitHub Flavored Markdown の仕様の例のうち、コードの書式の範囲に関わるもの（入れ子のバッククォート、字下げのコードブロック、閉じていないフェンス） |
