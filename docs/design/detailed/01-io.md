# 外との境

`plugin/src/io/`（外との境の層。[README][readme] の「層と依存の向き」）の作りを決める。
外との境は、入口が作ったシステム（外に触れる Node の機能をまとめた値）を引数で受け、外のコマンド・ファイル・OS を決まった形で呼ぶ。判断はせず、外から返ったものを決まった形の結果にして返す。結果をどう扱うか（止めるか、次の実行に回すか）は、流れの層が決める。

- 外から返ったものを読む処理（GitHub の API の失敗、`ps` と `lsof` の出力、`stream-json` の 1 行）は、外との境のファイルの中に置く。読む処理は外に触れないので、単体テストで出力の見本を渡して確かめる
- 外との境のファイルは、呼ぶ外のもの 1 つごとに分け、流れの層からは型だけで import される（[README][readme] の「層と依存の向き」）

## システム

入口（`entry/system.ts`）が、外に触れる Node の機能を次の形にまとめて作る。外との境は、システムのほかの方法で外に触れない。

| 名前 | 中身 | 入口が使う Node の機能 |
| --- | --- | --- |
| `spawn` | 子プロセスを起こす（コマンド、引数、作業フォルダ、環境変数、新しいプロセスグループにするか）。子プロセスの PID と、標準入力・標準出力・標準エラーと、終わりを待つ口を返す | `node:child_process` の `spawn` |
| `kill` | プロセスかプロセスグループに、シグナルを送る | `process.kill` |
| `fs` | ファイルの操作（読む、権限を付けて書く、追記してディスクへ書き出す、無いときだけ作る形で開いて書き、ディスクへ書き出して閉じる（`open` の `wx` と `fsync`）、`link`、`rename`、`lstat`、`chmod`、`realpath`、フォルダを作る（`mkdir`）、フォルダの一覧、リンクをたどらない削除） | `node:fs/promises` |
| `now`、`sleep` | 今の時刻（エポックのミリ秒）と、待つこと（待つ時間と、取り消しの `AbortSignal` を受け、取り消されたらすぐ終える） | `Date.now`、`setTimeout` と `clearTimeout` |
| `randomBytes` | 乱数 | `node:crypto` の `randomBytes` |
| `env` | 入口が起こされたときの環境変数の写し（読むだけ） | `process.env` |
| `platform`、`uid`、`pid` | OS の名前、ユーザーの ID、自分の PID | `process` |
| `hostname` | ホスト名（入口が起こされたときの値。読むだけ） | `node:os` の `hostname` |
| `fetch` | HTTPS で送る（GitHub の API と、GitHub の外への通知と device flow） | `fetch` |
| `listen` | 手元の戻り先を待つ（`127.0.0.1` と `::1`。FACT-95） | `node:http` |

- システムは、外に触れる道具だけを持ち、GitHub の API や `git` のことは知らない。外との境のファイルが、システムの上に呼び方を組み立てる
- 子プロセスの環境変数は、呼ぶ側が全部を渡す。`env` から引き継ぐのは、呼ぶ側が名前を選んで写したものだけにする（進行 Bot の環境変数を、名前を選ばずに子プロセスへ渡さない。[SAFE-1][safety]）
- 流れの層には、システムのうち `now`・`sleep`・`randomBytes` だけを持つ `FlowSystem` を渡す（[README][readme] の「層と依存の向き」）。ほかの道具は、外との境のファイルを通してだけ使う
- システムの道具は、Node の機能が投げる失敗を、`code` の欄（`ENOENT`・`EEXIST`・`ESRCH`・`EPERM` など）を持ったまま投げる。どの `code` を何と読むかは、外との境のファイルが決める。単体テストの偽物も、同じ `code` の失敗を投げる
- 標準エラーへの書き出しは、入口だけが行い、システムには持たない。`main.ts` は、`runs.jsonl` に書かない終わり方（マシンの設定を読めない `machine-settings-unreadable`、動かさない OS の `unsupported-os`）のときに、`flow/run/run.ts` が返した 1 行を標準エラーに書く（「[1 回の実行の流れ][d08]」の「終わり方と終了コード」）

## 子プロセスの起こし方と止め方

`io/proc.ts` は、子プロセスを 1 つ起こして、終わるか、時間の上限を過ぎるか、出力が上限を超えるまで待ち、次のどれかの結果を返す。

![子プロセスの起こし方と止め方][fig-proc]

| 結果 | 中身 | 流れの層の扱い |
| --- | --- | --- |
| 終わった | 終了コードかシグナルと、標準出力と標準エラー | 呼ぶ外のものごとに、外との境のファイルが中身を読んで返す |
| 時間の上限を過ぎた | 止めるまでに出た標準出力と標準エラー | 子プロセスの種類ごとに、「[設定][b01]」の「子プロセスが時間の上限を過ぎたとき」の表で決める |
| 起こせなかった | 起こせなかった理由（コマンドが無いなど） | 時間の上限を過ぎたときと同じ扱いにする（止める側に倒す） |
| 出力が上限を超えた | 上限を超えたところで子プロセスを止めた（止め方は時間の上限を過ぎたときと同じ）。出た出力は返さない | 時間の上限を過ぎたときと同じ扱いにする（止める側に倒す）。記録には、失敗の理由を `output-limit` と書く |

- 時間の上限を過ぎたら、子プロセスに `SIGTERM` を送り、猶予の間に終わらなければ `SIGKILL` を送る（子孫にも送るときは下の箇条）。猶予の間に終わっても、結果は「時間の上限を過ぎた」にする。子プロセスが時間の上限より先に終わったら、上限の待ちを取り消す
- 時間の上限と猶予は、呼ぶ側が渡す。リポの設定を読む前（1 回の実行の流れの順 2〜4）は、プログラムに固定した 10 分と 10 秒（「[設定][b01]」の「子プロセスが時間の上限を過ぎたとき」）を、`logic/settings/` の固定の一覧から渡す。リポの設定を読まない入口（`setup`、人の `check`・`/dev-autopilot`・intake）が起こす子プロセスと、GitHub と HTTPS の呼び出し 1 つずつにも、同じ固定の 10 分と 10 秒を使う
- `git`・`ps`・`lsof` などは、進行 Bot と同じプロセスグループで起こす。呼ぶ側が子孫の見つけ方（`io/processes.ts` のプロセスの一覧）を渡したときは、時間の上限を過ぎたら、子プロセスと、親をたどって見つけた子孫に `SIGTERM` を送り、猶予の後に、たどり直して見つけた子孫と子プロセスに `SIGKILL` を送る（「[設定][b01]」の `run.commandMinutes` の「AI のセッションと同じ手順で止め」）。`io/git.ts` は渡す（`git` は `ssh`・`git-upload-pack`・`pack-objects` を子に持ち、止まっているのはたいてい通信をする子孫のため）。`ps`・`lsof` は子を持たないので渡さない。子孫の見つけ方を引数で渡すのは、`io/proc.ts` が `io/processes.ts`（`ps` を `io/proc.ts` で起こす）を import すると、互いに import しあうため。親が PID 1 に替わった子孫はたどれないが、進行 Bot と同じプロセスグループに残る。進行 Bot が終わると（途中で落ちたときも）、定期の実行の launchd が、同じプロセスグループに残ったプロセスを止める（launchd の `AbandonProcessGroup` の既定。基本設計の plist は `AbandonProcessGroup` を使わない）
- `claude` だけは、新しいプロセスグループの先頭として起こし、止めるときはプロセスグループにシグナルを送る（「[AI のセッション][b03]」の「止める手順」）。進行 Bot が落ちても launchd に止められないので、次の実行が「前の実行が残したセッション」で探す
- 秘密と、長い文（指示文、コメントの本文、要求の JSON）は、引数に置かず標準入力で渡す。同じユーザーのほかのプロセスから、引数は `ps` で読めるため（FACT-110）。標準入力は、渡した文を書いてから閉じる
- 標準出力と標準エラーは、終わるまでメモリに集める。合わせた大きさの上限は、プログラムに固定した 64 MiB（「[設定と記録][d02]」の「プログラムに固定する値」）。超えたら子プロセスを止めて「出力が上限を超えた」を返す。AI が作った大きな差分で進行 Bot が落ち、次の実行も同じ所で落ちることを防ぐため。`claude` の `stream-json` だけは、`io/claude.ts` が 1 行ずつ扱う

## GitHub の呼び方

`io/github.ts` は、GitHub の API を `@octokit/core` で呼ぶ（[ADR-20261107-001][adr-github]、「[導入と点検][b04]」の「依存」）。`gh` を使わない。

| 呼ぶもの | 形 |
| --- | --- |
| REST | `octokit.request('<メソッド> <パス>', <引数>)`。要求の本文も引数で渡す |
| GraphQL | `octokit.graphql(<操作>, <変数>)`。操作には必ず名前を付ける（偽の GitHub が名前で答えを選ぶため。「[テスト][b05]」の「偽物」） |
| Octokit に渡すもの | `request.fetch` にシステムの `fetch`（FACT-121）、`auth` にトークン（進行 Bot は `io/github-token.ts` から受け取るインストールのトークン、`setup` は `setup` 用の App の人の代わりのトークン、JWT で呼ぶ 2 つの API と `setup` のインストールの ID の読み取りは JWT）、`request.signal` に時間の上限で取り消す `AbortSignal`、`log` に何もしない関数。`baseUrl` は既定の `https://api.github.com` のまま変えない |

- 結果は、次の 4 つのどれかにする。Octokit の失敗の `status` では見分けない（取り消しにも、つながらない失敗にも `500` が付くため）。上から順に見分ける
  - 取り消した：`io/github.ts` が時間の上限で `AbortController` を取り消した（自分で付けた印で見る。失敗の種類は見ない）
  - GraphQL の誤り：答えに `errors` がある（`GraphqlResponseError`。HTTP の状態は 200）。部分の `data` は捨て、返さない
  - HTTP の状態あり：成功したか、失敗に `response`（HTTP の答え）がある。2xx でない状態も、外との境では失敗にせず、状態と見出しと本文のまま返す（404 を「無い」と読むかなどは、流れの層が決める）
  - つながらない：上のどれでもない失敗
- 流れの層は、読み取りでは、取り消した・GraphQL の誤り・つながらないの 3 つを読めなかったとして扱う（HTTP の状態ありの読み方は、流れの層が状態ごとに決める）。書き込みでは、HTTP の状態あり（2xx でない）を断られた、ほかの 3 つを届いたか分からないとして扱い、次の実行で読み直す（「[設定][b01]」の「子プロセスが時間の上限を過ぎたとき」の書き込みの行）
- 時間の上限は、要求 1 つ（ページを送るときは 1 ページ）ごとに、呼ぶ側が渡す（`run.commandMinutes`。リポの設定を読む前は固定の 10 分。「[設定][b01]」の「子プロセスが時間の上限を過ぎたとき」）。システムの `sleep` で待ち、過ぎたら `AbortController` で要求を取り消す。要求が先に終わったら、待ちを取り消す。`AbortSignal.timeout` は、システムの外のタイマーを使うので使わない
- ページは、見出しの `Link` の `rel="next"` をたどって 1 ページずつ呼ぶ。1 ページごとに HTTP の状態を確かめ、途中のページで失敗したら、読めたページだけで判断しない（失敗を返す）。ページ送りの部品（`@octokit/plugin-paginate-rest`）は足さない。依存を増やさず、途中のページの失敗の扱いを外との境の中で決めるため
- 再試行と回数制限の待ちの部品も足さない。失敗したときの扱いは、流れの層が決める（[README][readme] の「層と依存の向き」）
- 読み取りと書き込みは、関数を分ける（`read`・`write`）。時間の上限を過ぎたときの扱いが、読み取りと書き込みで違うため（「[設定][b01]」の「子プロセスが時間の上限を過ぎたとき」）
- トークンと JWT は `auth` でだけ渡し、子プロセスの引数と環境変数、記録、ログに書かない（[SAFE-15][safety]）。`log` に何もしない関数を渡すのは、Octokit が標準エラーに書かないようにするため（失敗は結果で返す）。トークンと JWT は秘密の値の型で受け、`auth` に渡すときだけ `revealSecret` で中身を取り出す（下の「秘密の置き場」）
- App の作成の引き換え（`POST /app-manifests/{code}/conversions`。認証なし。「[導入と点検][b04]」の「GitHub App を作る」）も、`io/github.ts` で `auth` を渡さずに呼ぶ。答えの `pem` は秘密の値の型に入れて返し、`client_secret` と `webhook_secret` は返さずに捨てる（[ADR-20261030-001][adr-setup-app] の決定 2 の「置かない」）
- インストールのトークンへの引き換えの答えの `token` も、`io/github.ts` が秘密の値の型に入れて返す。持つのは `io/github-token.ts` で、外に出さない

## インストールのトークン

`io/github-token.ts` は、進行 Bot の GitHub App のインストールのトークンを、進行 Bot のプロセスの中でだけ持つ（[SAFE-15][safety]、「[導入と点検][b04]」の「GitHub App の権限」）。

- GitHub の API を呼ぶ前に、持っているトークンの残りの時間を見て、10 分を切っていれば作り直す
- 作り直すときは、秘密の置き場の秘密鍵（`io/secrets.ts` で読み、秘密の値の型のまま）を `io/github-jwt.ts` に渡して JWT を作り（下の「JWT の作り方」）、インストールのトークンに引き換える
- 引き換えの要求は、基本設計の表の権限と、当てる先のリポだけを要求する（`permissions` と `repositories`）。下の点検の読み取りのほかは、このトークンだけを使う
- 点検の「インストールが読めるリポ」だけは、`readInstallationRepositories` で読む。関数の中で、`permissions` を Metadata の読み取りだけにし、`repositories` を付けない引き換えをして、そのトークンで `GET /installation/repositories` をページを送って読み、リポの名前（`full_name`）の一覧だけを返す（「[導入と点検][b04]」の「GitHub App の権限」）。当てる先のリポに絞ったトークンでは、App がほかのリポに入っていても 1 件だけが返る（FACT-124）。このトークンは関数の外に出さず、持ち回らず、作り直しの対象にしない
- JWT とトークンは、ファイル・記録・ログに書かない。失敗したときの記録には、HTTP の状態と GitHub の `message` だけを書く

## JWT の作り方

`io/github-jwt.ts` は、進行 Bot の App の JWT を作る。秘密鍵は秘密の値の型で受け、秘密の置き場を読まない。進行 Bot（`io/github-token.ts` が秘密の置き場から読んだ鍵）と `setup`（App の作成の引き換えで受け取り、メモリに持つ鍵。「[導入と点検][b04]」の「GitHub App を作る」）が使う。

- JWT は `node:crypto` の `sign` で作る（`RS256`）。発行の時刻は今の 60 秒前（GitHub とマシンの時計のずれに備える）、期限は今から 9 分後（GitHub が受ける期限の上限は 10 分）にする。発行の時刻と期限をこう決めた JWT で、試し用 App の `GET /app` と引き換えが通った（FACT-107・109・124 の試し）
- 秘密鍵の中身は、署名するときだけ `revealSecret` で取り出す（下の「秘密の置き場」）
- `setup` は、進行 Bot の App を作った実行の中で、人が App を入れた後に、この JWT で `GET /repos/{owner}/{repo}/installation` を読み、インストールの ID を得る（「[setup][d05]」の「GitHub の準備の順」）。読めなかったとき（人が待つ時間の内に入れなかった、App がすでにあってインストールの ID が無い）は、`setup` は秘密鍵を読まずに人にインストールの ID を聞く。書いた ID が進行 Bot の App のものかは、`setup` の最後の点検（アプリの権限の組が、進行 Bot の JWT で `GET /app/installations/{installation_id}` を読む）が確かめ、違えば fail になる

## JWT で呼ぶ 2 つの API

インストールのトークンへの引き換え（`POST /app/installations/{installation_id}/access_tokens`）と、点検のインストールの情報の読み取り（`GET /app/installations/{installation_id}`）は、JWT を `@octokit/core` の `auth` に渡して呼ぶ（[ADR-20261107-001][adr-github]）。

- Octokit は、`.` で 3 つに区切られたトークンを JWT として、`Authorization` を `bearer` の形で送る（FACT-122）。GitHub は JWT を `Bearer` の形でだけ受ける（FACT-107）
- 引き換えの本文に、基本設計の表の権限（`permissions`）と、当てる先のリポ（`repositories`）を入れる。試し用 App で、絞った引き換えと、引き換えたトークンでの読み取りが通った（FACT-122・124）。点検の `readInstallationRepositories` の引き換えだけは、`permissions` を Metadata の読み取りだけにし、`repositories` を入れない（上の「インストールのトークン」）
- App の認証の部品（`@octokit/auth-app`）は使わない。Octokit に組み込む形では、引き換えで権限とリポを絞らないため（FACT-122）

## git の呼び方

`io/git.ts` は、進行 Bot の clone と、AI のセッションの作業場所を作るときの `git` を、決まった環境で呼ぶ。AI のセッションを起こした後の作業場所の clone では、取り込みの fetch のほかに `git` を呼ばない（[ADR-20261013-001][adr-workspace]。どの場面で呼ぶかは流れの層が決める）。

| 環境変数・設定 | 値 | 理由 |
| --- | --- | --- |
| `PATH`、`HOME`、`LANG` | `PATH` と `HOME` は進行 Bot の値、`LANG` は `C` | 出力を決まった言葉で読むため |
| `GIT_CONFIG_GLOBAL`、`GIT_CONFIG_NOSYSTEM` | `/dev/null`、`1` | ホームの個人設定とシステムの設定を読まない（「[状態遷移と判定][b02]」の「push の手順」） |
| `GIT_ATTR_NOSYSTEM` | `1` | システムの属性のファイルを読まない。属性のファイルは、`GIT_CONFIG_GLOBAL` と `GIT_CONFIG_NOSYSTEM` では止まらない（ホームの属性のファイルは、下の `core.attributesFile` で止める） |
| `GIT_TERMINAL_PROMPT` | `0` | 人に入力を求めて止まったまま待たない |
| `GIT_SSH_COMMAND` | 「[設定][b01]」の「秘密の置き場のファイル」の固定の形 | origin とやりとりする `git`（AI の作業場所と進行 Bot の clone を作る `clone`、origin からの `fetch`、`ls-remote`、`push`）に渡す。ほかの `git`（AI の作業場所からの取り込みの `fetch`、`merge`、`show`、`diff` など）には渡さない（[SAFE-15][safety]、[ADR-20261013-001][adr-workspace] の「clone の認証は進行役の鍵で行い」） |
| `GIT_CONFIG_COUNT`、`GIT_CONFIG_KEY_<n>`、`GIT_CONFIG_VALUE_<n>` | `core.hooksPath`＝`<置き場>/empty-hooks`、`commit.gpgsign`＝`false`、`core.attributesFile`＝`/dev/null` | 進行 Bot の clone の決まり（「[状態遷移と判定][b02]」の「push の手順」、[SAFE-16][safety]）。clone の設定ファイルに頼らず、呼ぶたびに環境変数で渡す（環境変数で渡せることは FACT-17）。`core.attributesFile` は、ホームの属性のファイル（`~/.config/git/attributes`）を読まないため |
| `GIT_AUTHOR_NAME`・`GIT_AUTHOR_EMAIL`・`GIT_COMMITTER_NAME`・`GIT_COMMITTER_EMAIL` | 投稿に使うアカウントの名前と、GitHub の noreply のアドレス | 載せ直しの merge の commit の作者（同上）。commit を作るときだけ渡す |

- 読み取り（進行 Bot の clone の fetch など）と、push と取り込み（`git push`、push の手順の fetch と merge）は、関数を分ける。時間の上限を過ぎたときの扱いが違うため
- deploy key は、`ssh` の `-i` にファイルのパスで渡し、中身を読まない
- origin とやりとりするかは、`io/git.ts` の関数ごとに決め、引数で選ばせない。渡し忘れた `git` が、`HOME` の下の人の `~/.ssh/config` と鍵を使わないため。origin とやりとりする関数は、clone、origin からの fetch、`ls-remote`、push の 4 つ
- 漏えいの検査に渡す差分（範囲の commit ごとの差分、merge の commit の `git show --cc`、マージの判定の最終の head の差分）は、`--text --no-textconv --no-ext-diff` を付けて読む。リポの `.gitattributes` の `-diff`・`binary` と、NUL を含むファイルでも、中身の行を出すため（FACT-129）。push は blob の中身を GitHub に届けるので、漏えいの検査は表示の属性に依らず中身を見る。検疫に掛ける差分と AI に渡す差分は付けずに読み、GitHub に書く文と AI に渡す文そのものを検疫する（git が binary とみなすファイルは、書く文にも渡す文にも中身が入らない）。付け忘れた読み方が混じっても、漏えいの検査が `binary-diff` で止める（「[文の検査と受け入れ][d06]」の「漏えいの検査」）
- `io/git.ts` は、進行 Bot の `git` を呼ぶ前に毎回、`<置き場>/empty-hooks/` が、リンクでないフォルダで、自分の持ち物で、権限が 700 で、中が空であることを `io/files.ts` で確かめる。無ければ「フォルダを作る」で作る。外れたら `git` を呼ばずに、起こせなかったとして返す（上の「子プロセスの起こし方と止め方」のとおり止める側に倒す）。進行 Bot が作り、`setup` は作らない（`known_hosts` と同じく、作る担い手を 1 か所にする）
- 人の Skill が開いているプロジェクトの origin の URL を読むときは、hook を動かさない読み取り（`git remote get-url origin`）だけの関数を使う。人の Skill の `git` は進行 Bot の `git` でないので、`empty-hooks/` を確かめない（人の Skill の sandbox から置き場に書けないため）

## claude の起こし方

`io/claude.ts` は、「[AI のセッション][b03]」の「起動の形」の引数と環境変数（`logic/session/` が組み立てる）で `claude` を起こす。

- 新しいプロセスグループの先頭として起こし、PID（プロセスグループの番号と同じ）を返す。起こした直後に、プロセスの起動の時刻とマシンの起動の時刻を `io/os.ts` で取る（「止める手順」の順 1）
- 指示文と渡す文は、標準入力に書いてから閉じる
- 標準出力の `stream-json` は、1 行ずつ読み、行ごとに呼ぶ側へ渡す（費用の数え方と出力契約の取り出しは `logic/session/` と `logic/text/`）。JSON として読めない行は、読めなかった行として渡す。1 行の長さの上限は、プログラムに固定した 16 MiB（「[設定と記録][d02]」の「プログラムに固定する値」）。超えた行は、次の改行までを捨てて読めなかった行として渡し、捨てた分をメモリに持たない。`result` の行が上限を超えたときは、出力契約を取り出せない（`contract-invalid`。「[文の検査と受け入れ][d06]」の「出力契約」）
- 受けた行は、記録の置き場の `streams/` のファイルに足す。`.jsonl` は書くたびにディスクへ書き出す決まり（「[状態遷移と判定][b02]」の「手元の記録」）なので、行をためて 1 秒ごとと終わったときに足し、足すたびに書き出す。1 行ごとに書き出すと、途中の文の行が多いときに遅くなるため
- 標準エラーは、記録の置き場に書く
- 止めるときは、プロセスグループに `SIGTERM` を送り、猶予の後に `SIGKILL` を送る（「止める手順」の順 2・3）。いつ止めるか（時間の上限、全体の止める合図）は、流れの層が決める

## プロセスの一覧と開いているファイル

`io/processes.ts` は、止める手順と前の実行が残したセッションで使う 2 つの読み取りと、lock の持ち主の確かめ（「[設定と記録][d02]」の「lock」）で使うプロセスがあるかの読み取りの、3 つを受け持つ（「[AI のセッション][b03]」の「止める手順」）。どれを止めるかは、流れの層と `logic/session/` が決める。

| 読み取り | 呼び方 | 結果 |
| --- | --- | --- |
| プロセスの一覧 | `LANG=C ps -A -o pid=,ppid=,pgid=` | PID・親の PID・プロセスグループの番号の一覧。プロセスの起動の時刻は、`io/os.ts` で PID ごとに取る |
| フォルダの中を作業フォルダにしているか、開いているプロセス | `lsof -n -P -F pcn +D <フォルダ>`。呼ぶ側が `lstat` であると確かめたフォルダにだけ使う（「[AI のセッション][d07]」の「止める相手と前の実行の残り」） | 見つけた（PID・コマンドの名前・開いているファイルの種類（作業フォルダは `cwd`）の一覧）・見つからなかった・探し切れなかった（下の箇条） |
| プロセスがあるか | システムの `kill` に、PID とシグナル 0 を渡す | ある（失敗が無いか `EPERM`。`EPERM` はほかのユーザーのプロセス）・無い（`ESRCH`）・分からない（ほかの失敗）（FACT-117） |

- `lsof` の結果は、終了コードでなく、標準出力と標準エラーで見分ける。何も見つからないときと失敗したときはどちらも終了コード 1 で（FACT-115）、見つけたときも、フォルダの木に開かれていないファイルがあれば終了コード 1 で終わる（FACT-128）
  - 見つけた：標準エラーが空で、終了コードが 0 か 1 で、標準出力に `p` の行がある。行を読んで一覧を返す
  - 見つからなかった：標準エラーが空で、終了コードが 1 で、標準出力が空
  - 探し切れなかった：ほかのすべて（標準エラーに文がある（警告の `lsof: WARNING` を含む）、終了コードが 0 なのに `p` の行が無い、標準出力に `-F pcn` の形でない行がある、ほかの終了コード、時間の上限を過ぎた、出力が上限を超えた）。見つけた行があっても、標準エラーに文があれば探し切れなかったにする。流れの層が `session-not-stopped` で止める（止める側に倒す）
- 無いフォルダを `lsof +D` に渡すと、警告を出して終了コード 1 で終わり、探し切れなかったになる（FACT-115）。探すフォルダが無いときの扱い（見つからなかったとする）は、呼ぶ側が決める（「[AI のセッション][d07]」の「止める相手と前の実行の残り」）
- 時間の上限は、`run.commandMinutes`。前の実行が残したセッションでは、プログラムに固定した 10 分（「[設定][b01]」の「子プロセスが時間の上限を過ぎたとき」）

## ファイル

`io/files.ts` は、次の操作を受け持つ。

| 操作 | 作り方 | 使う所 |
| --- | --- | --- |
| 排他の作成 | 中身を書いた一時のファイル（`<名前>.new-<自分の PID>`）をディスクへ書き出して（`fsync`）から、`link` で名前を付け、一時のファイルを、作れても作れなくても消す | lock（「[状態遷移と判定][b02]」の「1 回の実行の流れ」の「lock の取り方」） |
| 退ける | `rename` で、プロセスごとに違う名前（`<名前>.stale-<自分の PID>`）に変える | 古い lock を奪うとき（同上） |
| 1 行を足す | 追記で開き、ファイルが空でなければ最後の 1 バイトを読む。改行で終わっていなければ（切れた行がある）、書かずに「切れた行の後」の失敗を返す。終わっていれば、行を書き、ディスクへ書き出して（`fsync`）閉じる | `.jsonl` の記録（「[状態遷移と判定][b02]」の「手元の記録」） |
| 新しく書く | 無いときだけ作る形で開き、権限を付けて書き、ディスクへ書き出す | 出力契約の `.json`、`setup` が書く秘密のファイル（600） |
| 置き換える | 同じ名前のファイルがあれば、リンクをたどらずに消してから、「新しく書く」と同じく無いときだけ作る形で開き、権限を付けて書き、ディスクへ書き出す（消した後にほかのものが置かれていれば、作れずに失敗する） | 安全設定のファイル（600。「[AI のセッション][b03]」の「セッションごとの安全設定」の作り方の順 2） |
| フォルダを作る | 作った後に `chmod` で権限を付け直し、`lstat` で権限・持ち主・リンクでないことを確かめる（umask で権限が変わるのを見逃さない） | 置き場、短い一時フォルダの根と ID のフォルダ（「[AI のセッション][b03]」の「短い一時フォルダ」）、git の hook の空のフォルダ（`empty-hooks/`。上の「git の呼び方」） |
| 実体のパス | `realpath` | 短い一時フォルダ、安全設定のパス（同上） |
| 消す | `fs.rm` の `recursive`（リンクの先をたどらない。FACT-116）。`git` を使わない | 作業場所と短い一時フォルダ（[SAFE-12][safety]、同上の順 5） |

## 秘密の置き場

`io/secrets.ts` は、秘密の置き場のファイルを読む（「[設定][b01]」の「秘密の置き場のファイル」）。

- 読んだ中身の前後の空白と改行を除き、空なら「無い」として返す
- 読んだ値は、秘密の値の型（`logic/secret.ts`。何も import しない判断の層のファイル）に入れて返す。秘密の値の型は、中身を型の外から読めない形で持ち、文字列に変えたとき・JSON にしたとき・ログに出したときに、中身の代わりに `[secret]` を出す
- 中身を取り出す関数（`revealSecret`）は 1 つにし、import してよいファイルを構成の検査の一覧に持つ（[README][readme] の「構成の検査に足すこと」）。今の一覧は、`io/github.ts`（Octokit の `auth` に渡すとき）、`io/github-jwt.ts`（JWT の署名）、`io/http.ts`（Webhook の URL に送るとき）、`logic/marker/keys.ts`（印の署名の鍵の行を解くとき）、`logic/marker/sign.ts`（HMAC を掛けるとき）、`logic/text/leak.ts`（書いてあるままの文字と照らすとき）。解いた鍵のように、取り出した値から作った秘密も、秘密の値の型に入れ直して渡す
- 型を判断の層に置くのは、判断の層（印の署名と漏えいの検査）と、`setup` が使う外との境（`io/github.ts`・`io/http.ts`）が、秘密の置き場を読むモジュールに届かずに型を使えるようにするため
- deploy key は、パスで `ssh` に渡すので読まない（上の「git の呼び方」）
- 読めなかったときの記録には、ファイルの名前だけを書き、中身を書かない
- `io/secrets.ts` を実行時に import してよいのは、`main.ts` と `io/github-token.ts` だけ（流れの層は型だけ。[README][readme] の「入口ごとの import の範囲」）。`setup` が秘密のファイルを作って書くときは、`io/files.ts` の「新しく書く」を使う

## HTTPS

`io/http.ts` は、システムの `fetch` で HTTPS の JSON を送り、HTTP の状態と本文を返す。時間の上限を過ぎたときと、つながらないときは、HTTP の状態の無い失敗として返す。要求が先に終わったら、時間の上限の待ちを取り消す。
GitHub の外への通知の 1 回の送信の上限は、プログラムに固定した 30 秒（「[設定と記録][d02]」の「プログラムに固定する値」）で、`run.commandMinutes`（子プロセスと GitHub の API の呼び出しの上限）は使わない。送り直しの回数と間隔（「[1 回の実行の流れ][d08]」の「全体の停止と通知」）と掛け合わせた長さが、通知で lock を持つ長さの上限になる。device flow の 1 回の要求の上限は、リポの設定を読まない入口の固定の 10 分（上の「子プロセスの起こし方と止め方」）。

| 送り先 | 使う所 | テスト |
| --- | --- | --- |
| GitHub の外への通知の Webhook（秘密の置き場の `notify-webhook-url`） | 「[状態遷移と判定][b02]」の「GitHub の外への通知」 | 単体テストは偽の `fetch`。結合テストは下の箇条 |
| `https://github.com/login/device/code` と `https://github.com/login/oauth/access_token`（device flow） | 「[導入と点検][b04]」の「setup 用の App」 | 単体テストだけ（「[テスト][b05]」の「偽物」） |

- `setup` の手元の戻り先は、システムの `listen` で `127.0.0.1` と `::1` の両方で待つ（FACT-95）。2 つのアドレスのどちらかで待てなければ、待てたほうも閉じて、失敗として返す（`setup` は理由を示して止まる）。ブラウザは `localhost` を `::1` で開くので、片方だけで待つと、戻りが届かずに待ち続けうるため。待つ上限は、`setup` が答えを待つ上限と同じ 30 分（「[setup][d05]」の「プロセスの分け方」）。過ぎたら待つのをやめ、失敗を返す
- device flow の答えの `access_token` は秘密の値の型に入れて返し、`refresh_token` は返さずに捨てる（「[導入と点検][b04]」の「setup 用の App」の「更新のトークンは使わずに捨てる」）
- 結合テストの Webhook の偽の送り先は、テストの一時フォルダに作るテスト用の CA の証明書で、手元に HTTPS の送り先（`https://127.0.0.1:<ポート>`）を立てる。テストの秘密の置き場の `notify-webhook-url` に偽の送り先の URL を書き、進行 Bot の入口を `NODE_EXTRA_CA_CERTS`（Node の標準の環境変数）にテスト用の CA を入れて起こす（FACT-114）。テスト用の CA は、偽の GitHub（「[テスト][b05]」の「偽物」）と同じものを使う。進行 Bot のプログラムに、テストのためだけの切り替えを持たない。URL は `https://` で始まるので、点検の決まり（「[設定][b01]」の「`check` が設定について確かめること」）にも当たる
- Webhook の URL は、送り先の値として渡すだけで、記録とログに書かない（[ADR-20261101-002][adr-notify]）。中身は、送るときだけ `revealSecret` で取り出す

## OS ごとの部分

`io/os.ts` は、システムの OS の名前で、OS ごとの部分（今は `io/os/darwin.ts`）を返す。ほかの OS（今は Linux を含む。`io/os/linux.ts` は UNDECIDED-93 を決めるまで作らない）では、動かさない OS の結果を返す。結果を受けた流れは、進行 Bot なら 1 回の実行の順 1（マシンの設定を読む順）の前に止まり（終わり方 `unsupported-os`。「[1 回の実行の流れ][d08]」の「終わり方と終了コード」）、人の `setup`・`check`・`/dev-autopilot`・intake の「下書き」は、動かさないことを示して終わる（「[導入と点検][b04]」の「Linux（systemd のユーザーのタイマー）」）。点検のマシンの組の OS の項目は、今のまま fail にする（重ねる守り。「[導入と点検][b04]」の「組と回数」）。

| 受け持つこと | macOS（`io/os/darwin.ts`） | 使う所 |
| --- | --- | --- |
| マシンの起動の時刻 | `sysctl -n kern.boottime` の `sec` | 止める手順の順 1、前の実行が残したセッション |
| プロセスの起動の時刻 | `TZ=UTC LANG=C ps -o lstart= -p <PID>` の出力を UTC の時刻として読み、エポック秒にする | lock、止める手順、前の実行が残したセッション（lock と同じ関数。「[状態遷移と判定][b02]」の「lock の取り方」） |
| 人の一時フォルダとキャッシュの場所 | `getconf DARWIN_USER_TEMP_DIR`、`getconf DARWIN_USER_CACHE_DIR` | セッションごとの安全設定（「[AI のセッション][b03]」の「セッションごとの安全設定」） |
| 定期の実行の登録と外し方 | `launchctl bootstrap gui/<uid> <plist>`、`launchctl bootout gui/<uid>/<Label>`、`launchctl print gui/<uid>/<Label>` | `setup`、点検（「[導入と点検][b04]」の「定期の実行の登録」） |
| 定期の実行と同じジョブを起こす | `launchctl kickstart gui/<uid>/<Label>`（`-k` を付けない） | 人の `check`・`/dev-autopilot`・intake の下書き（「[導入と点検][b04]」の「点検だけで動かす仕組み」） |
| 定期の実行に渡る環境変数 | `launchctl getenv <名前>`（名前ごとに 1 回。出力が空なら無い） | 点検のマシンの組（「[導入と点検][b04]」の「組と回数」のマシンの行。[ADR-20261107-001][adr-github]） |
| OS の版 | `sw_vers` | 点検のマシンの組 |
| ホスト名 | システムの `hostname`（OS で変わらないので、`io/os.ts` の共通の部分で返す） | lock とプロセスの行（人が読むためだけ。「[状態遷移と判定][b02]」の「1 回の実行の流れ」の「lock の取り方」） |

- Linux（`io/os/linux.ts`）は、UNDECIDED-93 を決めるまで作らない。決めたら、マシンの起動の時刻は `/proc/stat` の `btime`、プロセスの起動の時刻は `/proc/<PID>/stat` に `btime` を足して取る（「[状態遷移と判定][b02]」の「lock の取り方」）。登録は `systemctl --user`（「[導入と点検][b04]」の「Linux（systemd のユーザーのタイマー）」）
- plist の中身（キーと値）は、`logic/` で組み立てる。外との境は、組み立てたファイルを書いて `launchctl` を呼ぶだけ

## テスト

外との境のファイルは、どれもシステムの型に合う偽物を引数で渡して単体テストする（[README][readme] の「テストで外との境を差し替える方法」）。`logic/secret.ts`（判断の層）は、値を渡して確かめる。ファイルごとに、次を確かめる。

| ファイル | 単体テストで確かめること |
| --- | --- |
| `io/proc.ts` | 時間の上限で `SIGTERM`、猶予の後に `SIGKILL` を送ること。猶予の間に終わっても「時間の上限を過ぎた」になること。渡したほかの環境変数を子プロセスに渡さないこと。標準入力を閉じること。子プロセスが先に終わったら、待ちを取り消すこと（偽の `sleep` が取り消しを受けたこと）。子孫の見つけ方を渡したとき、時間の上限で子孫にも `SIGTERM` と `SIGKILL` を送り、`SIGKILL` の前にたどり直すこと。出力が上限を超えたら子プロセスを止め、「出力が上限を超えた」を返すこと |
| `io/github.ts` | システムの `fetch` を渡し、グローバルの `fetch` を使わないこと（グローバルの `fetch` を、呼ばれたら投げるものに替える）。4 つの結果の見分け方（見本は、`AbortError` に `status` 500 が付いた失敗、`RequestError` の 500 で `response` の無い失敗、`errors` と部分の `data` を持つ `GraphqlResponseError`、`response` のある 404）。ページを `Link` でたどり、途中で失敗したら失敗を返すこと。時間の上限で要求を取り消すこと。要求が先に終わったら、待ちを取り消すこと。JWT を `bearer`、トークンを `token` の形で送ること。App の作成の引き換えの答えの `pem` とインストールのトークンの `token` を秘密の値の型で返し、`client_secret` と `webhook_secret` を返さないこと |
| `io/github-token.ts` | 残りが 10 分を切ったときだけ作り直すこと。引き換えの本文に表の権限と当てる先のリポが入ること。トークンを記録に書かないこと。`readInstallationRepositories` の引き換えの本文が `{"permissions":{"metadata":"read"}}` だけで `repositories` を持たないこと。返すのがリポの名前の一覧だけで、トークンを持ち回らないこと |
| `io/github-jwt.ts` | JWT の発行の時刻と期限。秘密鍵を秘密の値の型で受けること |
| `io/git.ts` | origin とやりとりする 4 つの関数（clone・origin からの fetch・`ls-remote`・push）が `GIT_SSH_COMMAND` を渡し、ほかの関数が渡さないこと。決まった環境変数（`GIT_ATTR_NOSYSTEM` と、`GIT_CONFIG_COUNT` の組の `core.hooksPath`・`commit.gpgsign`・`core.attributesFile`）。`-c` を使わないこと。漏えいの検査に渡す差分を読む関数が `--text`・`--no-textconv`・`--no-ext-diff` を付けること。`empty-hooks/` が空でない・リンク・ほかの持ち物・権限違いのときに `git` を呼ばないこと。無ければ 700 で作ること。子孫の見つけ方を `io/proc.ts` に渡すこと |
| `io/claude.ts` | 新しいプロセスグループで起こすこと。行を呼ぶ側へ渡し、まとめて記録に足すこと。読めない行の扱い。1 行の長さの上限を超えた行を読めなかった行として渡すこと。止めるときにプロセスグループへ送ること |
| `io/processes.ts` | `ps` と `lsof -F` の出力の読み方。`lsof` を標準出力の `p` の行で見分けること（見本：見つけたのに終了コード 1・標準エラー空（FACT-128）、終了コード 1・標準エラー空・標準出力空、警告がある、終了コード 0 で `p` の行が無い）。`kill` の失敗の符号ごとの読み方（失敗なし・`EPERM`・`ESRCH`・ほか） |
| `io/files.ts` | 排他の作成で、一時のファイルを書き出してから名前を付け、一時のファイルを消すこと。追記のたびに書き出すこと。改行で終わらないファイルに足さず、「切れた行の後」の失敗を返すこと。置き換えるで、あるファイルを消してから作ること。消した後に置かれたものがあれば失敗すること。フォルダの権限を付け直して確かめること |
| `io/secrets.ts` | 空のファイルを「無い」と読むこと。読んだ値を秘密の値の型で返すこと |
| `logic/secret.ts` | 秘密の値の型が、文字列・JSON・ログに中身を出さないこと。`revealSecret` だけが中身を返すこと |
| `io/http.ts` | 状態と本文の返し方。時間の上限を過ぎたときとつながらないときを、状態の無い失敗として返すこと。要求が先に終わったら、待ちを取り消すこと。`listen` の偽物で、受けた要求を返すこと。片方のアドレスで待てないときと、戻り先を待つ上限を過ぎたときに失敗を返すこと。device flow の `access_token` を秘密の値の型で返し、`refresh_token` を返さないこと |
| `io/os.ts` | システムの `platform` が `darwin` なら macOS の部分を返し、ほかの名前では動かさない OS の結果を返すこと。システムの `hostname` をホスト名として返すこと |
| `io/os/darwin.ts` | `kern.boottime` と `ps -o lstart=` の出力の読み方（時刻帯に依らないこと）。`kickstart` に `-k` を付けないこと。`launchctl getenv` の空の出力を「無い」と読むこと |
