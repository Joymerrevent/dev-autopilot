# 外との境

`plugin/src/io/`（外との境の層。[README][readme] の「層と依存の向き」）の作りを決める。
外との境は、入口が作ったシステム（外に触れる Node の機能をまとめた値）を引数で受け、外のコマンド・ファイル・OS を決まった形で呼ぶ。判断はせず、外から返ったものを決まった形の結果にして返す。結果をどう扱うか（止めるか、次の実行に回すか）は、流れの層が決める。

## ファイルの一覧

![外との境のファイル][fig-modules]

| ファイル | 受け持つこと | 呼ぶ外のもの | 基本設計 |
| --- | --- | --- | --- |
| `io/system.ts` | システムの型。型だけを書き、単体テストを持たない（[README][readme] の「テストで外との境を差し替える方法」） | — | — |
| `io/proc.ts` | 子プロセスを起こし、時間の上限で止め、終わり方と出力を返す | （システムの子プロセスとシグナル） | 「[設定][b01]」の「子プロセスが時間の上限を過ぎたとき」 |
| `io/github.ts` | `@octokit/core` で REST と GraphQL を呼び、HTTP の状態と本文を返す。ページを送る。時間の上限で要求を取り消す | GitHub の API（システムの `fetch`） | 「[導入と点検][b04]」の「依存」、「[テスト][b05]」の「偽物」 |
| `io/github-token.ts` | インストールのトークンを進行 Bot のプロセスの中でだけ持ち、残りが 10 分を切ったら作り直す | （下の「JWT で呼ぶ 2 つの API」） | 「[導入と点検][b04]」の「GitHub App の権限」 |
| `io/git.ts` | `git` を決まった環境で呼ぶ。push と fetch のときだけ deploy key の `ssh` を渡す | `git`、`ssh` | 「[設定][b01]」の「秘密の置き場のファイル」、「[状態遷移と判定][b02]」の「push の手順」 |
| `io/claude.ts` | `claude` を新しいプロセスグループで起こし、`stream-json` を 1 行ずつ渡しながら記録に書く | `claude` | 「[AI のセッション][b03]」の「起動の形」 |
| `io/processes.ts` | プロセスの一覧（PID・親・プロセスグループ）と、フォルダの中を作業フォルダにしているか開いているプロセスを読む | `ps`、`lsof` | 「[AI のセッション][b03]」の「止める手順」「前の実行が残したセッション」 |
| `io/files.ts` | ファイルとフォルダの操作（排他の作成、1 行の追記と書き出し、権限を確かめて作る、実体のパス、リンクをたどらない削除） | — | 「[状態遷移と判定][b02]」の「手元の記録」、「[AI のセッション][b03]」の「短い一時フォルダ」 |
| `io/secrets.ts` | 秘密の置き場のファイルを読む | — | 「[設定][b01]」の「秘密の置き場のファイル」 |
| `io/http.ts` | HTTPS で JSON を送る（GitHub の外への通知、`setup` の device flow）。`setup` の手元の戻り先を待つ | — | 「[状態遷移と判定][b02]」の「GitHub の外への通知」、「[導入と点検][b04]」の「setup 用の App」「GitHub App を作る」 |
| `io/os.ts` | システムの OS の名前から、OS ごとの部分を選ぶ | — | — |
| `io/os/darwin.ts` | macOS の部分（マシンの起動の時刻、プロセスの起動の時刻、人の一時フォルダの場所、定期の実行の登録と起こし方、OS の版） | `sysctl`、`ps`、`getconf`、`launchctl`、`sw_vers` | 「[状態遷移と判定][b02]」の「1 回の実行の流れ」の「lock の取り方」、「[導入と点検][b04]」の「定期の実行の登録」 |
| `io/os/linux.ts` | Linux の部分。UNDECIDED-93（Linux の安全設定）を決めるまで作らない。点検が Linux を fail にするので、呼ばれない（「[導入と点検][b04]」の「組と回数」） | — | 「[導入と点検][b04]」の「Linux（systemd のユーザーのタイマー）」 |

- 外から返ったものを読む処理（GitHub の API の失敗、`ps` と `lsof` の出力、`stream-json` の 1 行）は、外との境のファイルの中に置く。読む処理は外に触れないので、単体テストで出力の見本を渡して確かめる
- 外との境のファイルは、呼ぶ外のもの 1 つごとに分け、流れの層からは型だけで import される（[README][readme] の「層と依存の向き」）

## システム

入口（`entry/system.ts`）が、外に触れる Node の機能を次の形にまとめて作る。外との境は、システムのほかの方法で外に触れない。

| 名前 | 中身 | 入口が使う Node の機能 |
| --- | --- | --- |
| `spawn` | 子プロセスを起こす（コマンド、引数、作業フォルダ、環境変数、新しいプロセスグループにするか）。子プロセスの PID と、標準入力・標準出力・標準エラーと、終わりを待つ口を返す | `node:child_process` の `spawn` |
| `kill` | プロセスかプロセスグループに、シグナルを送る | `process.kill` |
| `fs` | ファイルの操作（読む、権限を付けて書く、追記してディスクへ書き出す、`link`、`rename`、`lstat`、`chmod`、`realpath`、フォルダの一覧、リンクをたどらない削除） | `node:fs/promises` |
| `now`、`sleep` | 今の時刻（エポックのミリ秒）と、待つこと | `Date.now`、`setTimeout` |
| `randomBytes` | 乱数 | `node:crypto` の `randomBytes` |
| `env` | 入口が起こされたときの環境変数の写し（読むだけ） | `process.env` |
| `platform`、`uid`、`pid` | OS の名前、ユーザーの ID、自分の PID | `process` |
| `fetch` | HTTPS で送る（GitHub の API と、GitHub の外への通知と device flow） | `fetch` |
| `listen` | 手元の戻り先を待つ（`127.0.0.1` と `::1`。FACT-95） | `node:http` |

- システムは、外に触れる道具だけを持ち、GitHub の API や `git` のことは知らない。外との境のファイルが、システムの上に呼び方を組み立てる
- 子プロセスの環境変数は、呼ぶ側が全部を渡す。`env` から引き継ぐのは、呼ぶ側が名前を選んで写したものだけにする（進行 Bot の環境変数を、名前を選ばずに子プロセスへ渡さない。[SAFE-1][safety]）

## 子プロセスの起こし方と止め方

`io/proc.ts` は、子プロセスを 1 つ起こして、終わるか時間の上限を過ぎるまで待ち、次のどれかの結果を返す。

![子プロセスの起こし方と止め方][fig-proc]

| 結果 | 中身 | 流れの層の扱い |
| --- | --- | --- |
| 終わった | 終了コードかシグナルと、標準出力と標準エラー | 呼ぶ外のものごとに、外との境のファイルが中身を読んで返す |
| 時間の上限を過ぎた | 止めるまでに出た標準出力と標準エラー | 子プロセスの種類ごとに、「[設定][b01]」の「子プロセスが時間の上限を過ぎたとき」の表で決める |
| 起こせなかった | 起こせなかった理由（コマンドが無いなど） | 時間の上限を過ぎたときと同じ扱いにする（止める側に倒す） |

- 時間の上限を過ぎたら、子プロセスに `SIGTERM` を送り、猶予の間に終わらなければ `SIGKILL` を送る。猶予の間に終わっても、結果は「時間の上限を過ぎた」にする
- 時間の上限と猶予は、呼ぶ側が渡す。リポの設定を読む前（1 回の実行の流れの順 2〜4）は、プログラムに固定した 10 分と 10 秒（「[設定][b01]」の「子プロセスが時間の上限を過ぎたとき」）を、`logic/settings/` の固定の一覧から渡す
- `git`・`ps`・`lsof` などは、進行 Bot と同じプロセスグループで起こし、時間の上限を過ぎたら子プロセスにだけシグナルを送る。進行 Bot が途中で落ちても、定期の実行の launchd が、同じプロセスグループに残ったプロセスを止める（launchd の `AbandonProcessGroup` の既定。基本設計の plist は `AbandonProcessGroup` を使わない）
- `claude` だけは、新しいプロセスグループの先頭として起こし、止めるときはプロセスグループにシグナルを送る（「[AI のセッション][b03]」の「止める手順」）。進行 Bot が落ちても launchd に止められないので、次の実行が「前の実行が残したセッション」で探す
- 秘密と、長い文（指示文、コメントの本文、要求の JSON）は、引数に置かず標準入力で渡す。同じユーザーのほかのプロセスから、引数は `ps` で読めるため（FACT-110）。標準入力は、渡した文を書いてから閉じる
- 標準出力と標準エラーは、終わるまでメモリに集める。`claude` の `stream-json` だけは、`io/claude.ts` が 1 行ずつ扱う

## GitHub の呼び方

`io/github.ts` は、GitHub の API を `@octokit/core` で呼ぶ（[ADR-20261107-001][adr-github]、「[導入と点検][b04]」の「依存」）。`gh` を使わない。

| 呼ぶもの | 形 |
| --- | --- |
| REST | `octokit.request('<メソッド> <パス>', <引数>)`。要求の本文も引数で渡す |
| GraphQL | `octokit.graphql(<操作>, <変数>)`。操作には必ず名前を付ける（偽の GitHub が名前で答えを選ぶため。「[テスト][b05]」の「偽物」） |
| Octokit に渡すもの | `request.fetch` にシステムの `fetch`（FACT-121）、`auth` にトークン（進行 Bot は `io/github-token.ts` から受け取るインストールのトークン、`setup` は `setup` 用の App の人の代わりのトークン、JWT で呼ぶ 2 つの API は JWT）、`request.signal` に時間の上限で取り消す `AbortSignal`、`log` に何もしない関数。`baseUrl` は既定の `https://api.github.com` のまま変えない |

- 結果は、HTTP の状態と見出しと本文を返す。2xx でない状態も、外との境では失敗にせず、状態のまま返す（Octokit が投げる失敗から、状態と本文を読む。404 を「無い」と読むかなどは、流れの層が決める）。つながらないときと、時間の上限で取り消したときは、HTTP の状態の無い失敗として返す
- 時間の上限は、要求 1 つ（ページを送るときは 1 ページ）ごとに、呼ぶ側が渡す（`run.commandMinutes`。リポの設定を読む前は固定の 10 分。「[設定][b01]」の「子プロセスが時間の上限を過ぎたとき」）。システムの `sleep` で待ち、過ぎたら `AbortController` で要求を取り消す。`AbortSignal.timeout` は、システムの外のタイマーを使うので使わない
- ページは、見出しの `Link` の `rel="next"` をたどって 1 ページずつ呼ぶ。1 ページごとに HTTP の状態を確かめ、途中のページで失敗したら、読めたページだけで判断しない（失敗を返す）。ページ送りの部品（`@octokit/plugin-paginate-rest`）は足さない。依存を増やさず、途中のページの失敗の扱いを外との境の中で決めるため
- 再試行と回数制限の待ちの部品も足さない。失敗したときの扱いは、流れの層が決める（[README][readme] の「層と依存の向き」）
- 読み取りと書き込みは、関数を分ける（`read`・`write`）。時間の上限を過ぎたときの扱いが、読み取りと書き込みで違うため（「[設定][b01]」の「子プロセスが時間の上限を過ぎたとき」）
- トークンと JWT は `auth` でだけ渡し、子プロセスの引数と環境変数、記録、ログに書かない（[SAFE-15][safety]）。`log` に何もしない関数を渡すのは、Octokit が標準エラーに書かないようにするため（失敗は結果で返す）
- App の作成の引き換え（`POST /app-manifests/{code}/conversions`。認証なし。「[導入と点検][b04]」の「GitHub App を作る」）も、`io/github.ts` で `auth` を渡さずに呼ぶ

## インストールのトークン

`io/github-token.ts` は、進行 Bot の GitHub App のインストールのトークンを、進行 Bot のプロセスの中でだけ持つ（[SAFE-15][safety]、「[導入と点検][b04]」の「GitHub App の権限」）。

- GitHub の API を呼ぶ前に、持っているトークンの残りの時間を見て、10 分を切っていれば作り直す
- 作り直すときは、秘密の置き場の秘密鍵（`io/secrets.ts` で読む）で JWT を作り、インストールのトークンに引き換える。JWT は `node:crypto` で作る（`RS256`）。発行の時刻は今の 60 秒前（GitHub とマシンの時計のずれに備える）、期限は今から 9 分後（GitHub が受ける期限の上限は 10 分）にする。発行の時刻と期限をこう決めた JWT で、試し用 App の `GET /app` と引き換えが通った（FACT-107・109・124 の試し）
- 引き換えの要求は、基本設計の表の権限と、当てる先のリポだけを要求する（`permissions` と `repositories`）
- JWT とトークンは、ファイル・記録・ログに書かない。失敗したときの記録には、HTTP の状態と GitHub の `message` だけを書く

## JWT で呼ぶ 2 つの API

インストールのトークンへの引き換え（`POST /app/installations/{installation_id}/access_tokens`）と、点検のインストールの情報の読み取り（`GET /app/installations/{installation_id}`）は、JWT を `@octokit/core` の `auth` に渡して呼ぶ（[ADR-20261107-001][adr-github]）。

- Octokit は、`.` で 3 つに区切られたトークンを JWT として、`Authorization` を `bearer` の形で送る（FACT-122）。GitHub は JWT を `Bearer` の形でだけ受ける（FACT-107）
- 引き換えの本文に、基本設計の表の権限（`permissions`）と、当てる先のリポ（`repositories`）を入れる。試し用 App で、絞った引き換えと、引き換えたトークンでの読み取りが通った（FACT-122・124）
- App の認証の部品（`@octokit/auth-app`）は使わない。Octokit に組み込む形では、引き換えで権限とリポを絞らないため（FACT-122）

## git の呼び方

`io/git.ts` は、進行 Bot の clone と、AI のセッションの作業場所を作るときの `git` を、決まった環境で呼ぶ。AI のセッションを起こした後の作業場所の clone では、取り込みの fetch のほかに `git` を呼ばない（[ADR-20261013-001][adr-workspace]。どの場面で呼ぶかは流れの層が決める）。

| 環境変数・設定 | 値 | 理由 |
| --- | --- | --- |
| `PATH`、`HOME`、`LANG` | `PATH` と `HOME` は進行 Bot の値、`LANG` は `C` | 出力を決まった言葉で読むため |
| `GIT_CONFIG_GLOBAL`、`GIT_CONFIG_NOSYSTEM` | `/dev/null`、`1` | ホームの個人設定とシステムの設定を読まない（「[状態遷移と判定][b02]」の「push の手順」） |
| `GIT_TERMINAL_PROMPT` | `0` | 人に入力を求めて止まったまま待たない |
| `GIT_SSH_COMMAND` | 「[設定][b01]」の「秘密の置き場のファイル」の固定の形 | push と、origin からの fetch のときだけ渡す。ほかの `git` には渡さない（[SAFE-15][safety]） |
| `-c core.hooksPath=<空のフォルダ>`、`-c commit.gpgsign=false` | — | 進行 Bot の clone の決まり（「[状態遷移と判定][b02]」の「push の手順」、[SAFE-16][safety]）。clone の設定ファイルに頼らず、呼ぶたびに渡す |
| `GIT_AUTHOR_NAME`・`GIT_AUTHOR_EMAIL`・`GIT_COMMITTER_NAME`・`GIT_COMMITTER_EMAIL` | 投稿に使うアカウントの名前と、GitHub の noreply のアドレス | 載せ直しの merge の commit の作者（同上）。commit を作るときだけ渡す |

- 読み取り（進行 Bot の clone の fetch など）と、push と取り込み（`git push`、push の手順の fetch と merge）は、関数を分ける。時間の上限を過ぎたときの扱いが違うため
- deploy key は、`ssh` の `-i` にファイルのパスで渡し、中身を読まない

## claude の起こし方

`io/claude.ts` は、「[AI のセッション][b03]」の「起動の形」の引数と環境変数（`logic/session/` が組み立てる）で `claude` を起こす。

- 新しいプロセスグループの先頭として起こし、PID（プロセスグループの番号と同じ）を返す。起こした直後に、プロセスの起動の時刻とマシンの起動の時刻を `io/os.ts` で取る（「止める手順」の順 1）
- 指示文と渡す文は、標準入力に書いてから閉じる
- 標準出力の `stream-json` は、1 行ずつ読み、行ごとに呼ぶ側へ渡す（費用の数え方と出力契約の取り出しは `logic/session/` と `logic/text/`）。JSON として読めない行は、読めなかった行として渡す
- 受けた行は、記録の置き場の `streams/` のファイルに足す。`.jsonl` は書くたびにディスクへ書き出す決まり（「[状態遷移と判定][b02]」の「手元の記録」）なので、行をためて 1 秒ごとと終わったときに足し、足すたびに書き出す。1 行ごとに書き出すと、途中の文の行が多いときに遅くなるため
- 標準エラーは、記録の置き場に書く
- 止めるときは、プロセスグループに `SIGTERM` を送り、猶予の後に `SIGKILL` を送る（「止める手順」の順 2・3）。いつ止めるか（時間の上限、全体の止める合図）は、流れの層が決める

## プロセスの一覧と開いているファイル

`io/processes.ts` は、止める手順と前の実行が残したセッションで使う 2 つの読み取りを受け持つ（「[AI のセッション][b03]」の「止める手順」）。どれを止めるかは、流れの層と `logic/session/` が決める。

| 読み取り | 呼び方 | 結果 |
| --- | --- | --- |
| プロセスの一覧 | `LANG=C ps -A -o pid=,ppid=,pgid=` | PID・親の PID・プロセスグループの番号の一覧。プロセスの起動の時刻は、`io/os.ts` で PID ごとに取る |
| フォルダの中を作業フォルダにしているか、開いているプロセス | `lsof -n -P -F pcn +D <フォルダ>` | PID・コマンドの名前・開いているファイルの種類（作業フォルダは `cwd`）の一覧 |

- `lsof` は、何も見つからないときと失敗したときを、終了コードで見分けられない（どちらも 1。FACT-115）。終了コードが 0 なら出力を読む。1 で標準エラーが空なら、見つからなかったと読む。ほかの終わり方（標準エラーに文がある、ほかの終了コード、時間の上限を過ぎた）は、探し切れなかったとして返し、流れの層が `session-not-stopped` で止める。警告（`lsof: WARNING`）も探し切れなかったものに数える（止める側に倒す）
- 時間の上限は、`run.commandMinutes`。前の実行が残したセッションでは、プログラムに固定した 10 分（「[設定][b01]」の「子プロセスが時間の上限を過ぎたとき」）

## ファイル

`io/files.ts` は、次の操作を受け持つ。

| 操作 | 作り方 | 使う所 |
| --- | --- | --- |
| 排他の作成 | 中身を書いた一時のファイル（`<名前>.new-<自分の PID>`）に `link` で名前を付け、一時のファイルを、作れても作れなくても消す | lock（「[状態遷移と判定][b02]」の「1 回の実行の流れ」の「lock の取り方」） |
| 退ける | `rename` で、プロセスごとに違う名前（`<名前>.stale-<自分の PID>`）に変える | 古い lock を奪うとき（同上） |
| 1 行を足す | 追記で開き、行を書き、ディスクへ書き出して（`fsync`）閉じる | `.jsonl` の記録（「[状態遷移と判定][b02]」の「手元の記録」） |
| 新しく書く | 無いときだけ作る形で開き、権限を付けて書き、ディスクへ書き出す | 出力契約の `.json`、安全設定のファイル（600）、`setup` が書く秘密のファイル（600） |
| フォルダを作る | 作った後に `chmod` で権限を付け直し、`lstat` で権限・持ち主・リンクでないことを確かめる（umask で権限が変わるのを見逃さない） | 置き場、短い一時フォルダの根と ID のフォルダ（「[AI のセッション][b03]」の「短い一時フォルダ」） |
| 実体のパス | `realpath` | 短い一時フォルダ、安全設定のパス（同上） |
| 消す | `fs.rm` の `recursive`（リンクの先をたどらない。FACT-116）。`git` を使わない | 作業場所と短い一時フォルダ（[SAFE-12][safety]、同上の順 5） |

## 秘密の置き場

`io/secrets.ts` は、秘密の置き場のファイルを読む（「[設定][b01]」の「秘密の置き場のファイル」）。

- 読んだ中身の前後の空白と改行を除き、空なら「無い」として返す
- 読んだ値は、秘密の値の型に入れて返す。秘密の値の型は、文字列に変えたとき・JSON にしたとき・ログに出したときに、中身の代わりに `[secret]` を出す。中身を取り出す関数は 1 つにし、外との境の中（JWT の署名、Octokit の `auth` に渡すとき、Webhook に送るとき）からだけ呼ぶ
- deploy key は、パスで `ssh` に渡すので読まない（上の「git の呼び方」）
- 読めなかったときの記録には、ファイルの名前だけを書き、中身を書かない
- `io/secrets.ts` を import してよいのは、進行 Bot の入口（`main.ts`）からたどれる流れだけ（[README][readme] の「入口ごとの import の範囲」）。`setup` が秘密のファイルを作って書くときは、`io/files.ts` の「新しく書く」を使う

## HTTPS

`io/http.ts` は、システムの `fetch` で HTTPS の JSON を送り、HTTP の状態と本文を返す。時間の上限を過ぎたときと、つながらないときは、HTTP の状態の無い失敗として返す。

| 送り先 | 使う所 | テスト |
| --- | --- | --- |
| GitHub の外への通知の Webhook（秘密の置き場の `notify-webhook-url`） | 「[状態遷移と判定][b02]」の「GitHub の外への通知」 | 単体テストは偽の `fetch`。結合テストは下の箇条 |
| `https://github.com/login/device/code` と `https://github.com/login/oauth/access_token`（device flow） | 「[導入と点検][b04]」の「setup 用の App」 | 単体テストだけ（「[テスト][b05]」の「偽物」） |

- `setup` の手元の戻り先は、システムの `listen` で `127.0.0.1` と `::1` の両方で待つ（FACT-95）
- 結合テストの Webhook の偽の送り先は、テストの一時フォルダに作るテスト用の CA の証明書で、手元に HTTPS の送り先（`https://127.0.0.1:<ポート>`）を立てる。テストの秘密の置き場の `notify-webhook-url` に偽の送り先の URL を書き、進行 Bot の入口を `NODE_EXTRA_CA_CERTS`（Node の標準の環境変数）にテスト用の CA を入れて起こす（FACT-114）。テスト用の CA は、偽の GitHub（「[テスト][b05]」の「偽物」）と同じものを使う。進行 Bot のプログラムに、テストのためだけの切り替えを持たない。URL は `https://` で始まるので、点検の決まり（「[設定][b01]」の「`check` が設定について確かめること」）にも当たる
- Webhook の URL は、送り先の値として渡すだけで、記録とログに書かない（[ADR-20261101-002][adr-notify]）

## OS ごとの部分

`io/os.ts` は、システムの OS の名前で、`io/os/darwin.ts` か `io/os/linux.ts` を返す。ほかの OS では、点検が fail にする（「[導入と点検][b04]」の「組と回数」）。

| 受け持つこと | macOS（`io/os/darwin.ts`） | 使う所 |
| --- | --- | --- |
| マシンの起動の時刻 | `sysctl -n kern.boottime` の `sec` | 止める手順の順 1、前の実行が残したセッション |
| プロセスの起動の時刻 | `TZ=UTC LANG=C ps -o lstart= -p <PID>` の出力を UTC の時刻として読み、エポック秒にする | lock、止める手順、前の実行が残したセッション（lock と同じ関数。「[状態遷移と判定][b02]」の「lock の取り方」） |
| 人の一時フォルダとキャッシュの場所 | `getconf DARWIN_USER_TEMP_DIR`、`getconf DARWIN_USER_CACHE_DIR` | セッションごとの安全設定（「[AI のセッション][b03]」の「セッションごとの安全設定」） |
| 定期の実行の登録と外し方 | `launchctl bootstrap gui/<uid> <plist>`、`launchctl bootout gui/<uid>/<Label>`、`launchctl print gui/<uid>/<Label>` | `setup`、点検（「[導入と点検][b04]」の「定期の実行の登録」） |
| 定期の実行と同じジョブを起こす | `launchctl kickstart gui/<uid>/<Label>`（`-k` を付けない） | 人の `check`・`/dev-autopilot`・intake の下書き（「[導入と点検][b04]」の「点検だけで動かす仕組み」） |
| OS の版 | `sw_vers` | 点検のマシンの組 |

- Linux（`io/os/linux.ts`）は、UNDECIDED-93 を決めるまで作らない。決めたら、マシンの起動の時刻は `/proc/stat` の `btime`、プロセスの起動の時刻は `/proc/<PID>/stat` に `btime` を足して取る（「[状態遷移と判定][b02]」の「lock の取り方」）。登録は `systemctl --user`（「[導入と点検][b04]」の「Linux（systemd のユーザーのタイマー）」）
- plist の中身（キーと値）は、`logic/` で組み立てる。外との境は、組み立てたファイルを書いて `launchctl` を呼ぶだけ

## テスト

外との境のファイルは、どれもシステムの型に合う偽物を引数で渡して単体テストする（[README][readme] の「テストで外との境を差し替える方法」）。ファイルごとに、次を確かめる。

| ファイル | 単体テストで確かめること |
| --- | --- |
| `io/proc.ts` | 時間の上限で `SIGTERM`、猶予の後に `SIGKILL` を送ること。猶予の間に終わっても「時間の上限を過ぎた」になること。渡したほかの環境変数を子プロセスに渡さないこと。標準入力を閉じること |
| `io/github.ts` | システムの `fetch` を渡し、グローバルの `fetch` を使わないこと（グローバルの `fetch` を、呼ばれたら投げるものに替える）。状態の返し方（200・404・つながらないとき・取り消したとき）。ページを `Link` でたどり、途中で失敗したら失敗を返すこと。時間の上限で要求を取り消すこと。JWT を `bearer`、トークンを `token` の形で送ること |
| `io/github-token.ts` | 残りが 10 分を切ったときだけ作り直すこと。JWT の発行の時刻と期限。引き換えの本文に表の権限と当てる先のリポが入ること。トークンを記録に書かないこと |
| `io/git.ts` | `GIT_SSH_COMMAND` を push と fetch のときだけ渡すこと。決まった環境変数と `-c` の設定 |
| `io/claude.ts` | 新しいプロセスグループで起こすこと。行を呼ぶ側へ渡し、まとめて記録に足すこと。読めない行の扱い。止めるときにプロセスグループへ送ること |
| `io/processes.ts` | `ps` と `lsof -F` の出力の読み方。`lsof` の終了コード 1 を、標準エラーが空のときだけ「見つからない」と読むこと |
| `io/files.ts` | 排他の作成で一時のファイルを消すこと。追記のたびに書き出すこと。フォルダの権限を付け直して確かめること |
| `io/secrets.ts` | 空のファイルを「無い」と読むこと。秘密の値の型が、文字列・JSON・ログに中身を出さないこと |
| `io/http.ts` | 状態と本文の返し方。時間の上限を過ぎたときとつながらないときを、状態の無い失敗として返すこと |
| `io/os/darwin.ts` | `kern.boottime` と `ps -o lstart=` の出力の読み方（時刻帯に依らないこと）。`kickstart` に `-k` を付けないこと |
