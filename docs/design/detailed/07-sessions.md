# AI のセッション

AI のセッションを準備し、起こし、見張り、止め、費用を数える処理の作りを決める。
起動の形・環境変数・短い一時フォルダ・安全設定・上限・起動の前の確かめ・止める手順・前の実行が残したセッション・費用の数え方・レビューの軸の起こし方の正本は、基本設計の「[AI のセッション][b03]」にある。本書は、正本を並べ直さず、ファイルの分け方、1 つのセッションの順と終わり方、費用の取り置き、入力の欄の区切りの形を決める。

| `logic/session/stop-targets.ts` | 判断 | プロセスの一覧から、止める相手のプロセスグループを決める処理と、`claude` の子孫のプロセスグループの控えの更新 | 同上の「止める手順」 |

| `flow/session/prepare.ts` | 流れ | セッションの順 2〜4（短い一時フォルダの根と ID、セッションのフォルダの作り直し、短い一時フォルダ、clone と worktree、`canon/` と `tmp/`、安全設定のファイル）。AI の作業場所の clone は `io/git.ts` の clone の関数で作る。安全設定のファイルは `io/files.ts` の「置き換える」で書く | 同上の「セッションの名前」「短い一時フォルダ」「セッションごとの安全設定」 |

| `flow/session/stop.ts` | 流れ | 止める手順と、残りの探し方 | 同上の「止める手順」 |
| `flow/session/leftovers.ts` | 流れ | 前の実行が残したセッションの片付け。結果（止めたセッション、止められなかったセッション（名前・始まりの行の値・作業の単位と PR。作業の単位を持たないセッションは PID とフォルダ）、前の実行が残したセッションの順 3 の全体の探し方で見つけたプロセス（人に渡したセッションのフォルダの中のものと、ほかのもの。PID・コマンドの名前・フォルダ））を返す。停止中にした後の終わりの行を書く処理（前の実行が残したセッションと、今の実行の `not-stopped` の両方で使う） | 同上の「前の実行が残したセッション」 |
| `flow/session/review-round.ts` | 流れ | レビューの 1 ラウンド（3 つの軸を並べて起こし、見落としの軸、批評 AI） | 同上の「レビューの軸の起こし方」 |

- `claude` を起こし `stream-json` を 1 行ずつ渡すのは外との境の `io/claude.ts`、プロセスの一覧と開いているファイルを読むのは `io/processes.ts`（「[外との境][d01]」）
- 判断の層のファイルは、時刻・プロセス・ファイルの情報を引数で受ける。止める相手の見分けと探し方 1 の判定のように、誤ると人のプロセスを止めうる処理を、単体テストで組み合わせごとに確かめられるようにするため

## セッションの順

![1 つのセッションの順][fig-lifecycle]

`flow/session/run.ts` は、1 つのセッションを次の順で動かし、終わり方の記号を返す。流れの層の工程は、終わり方の記号で扱いを決める（実行の失敗にするか、停止中にするか、次の工程へ進むか）。表の「起動の前の確かめの順」は、「[AI のセッション][b03]」の「起動の前の確かめ」の表の番号。

| セッションの順 | すること | 記録（`sessions.jsonl`。「[設定と記録][d02]」の「手元の記録」） | 外れたとき |
| --- | --- | --- | --- |
| 1. 起動の前の確かめ（合図・費用・入力） | `flow/safety/signal.ts` で全体の止める合図と全体の停止の Issue の有無を読み直し（点検の試しのセッション（名前が `check-` で始まる）と、受け入れの依頼の実行の受付 AI（名前が `verify-intake-issue-` で始まる）のときは、作業の単位の Issue の印も読み、開き直しの条件に当たる作業の単位があるか読めなければ、全体の停止の Issue を「ある」にする。定期の実行の下書きと書き直しの受付 AI は、順 7 の後の開き直しを済ませてから起こすので読み足さない。「[1 回の実行の流れ][d08]」の「全体の停止と通知」）、`RunContext` の合図を入れ替える（全体の停止の Issue の「ある」は、実行の中で「無い」に戻さない。見つかりの記録（記録の置き場の `security-pending/`。実行の順 2 で読む。「[設定と記録][d02]」の「手元の記録」）があるか読めないときも、`RunContext` の全体の停止の Issue は「ある」で、読み直しても「無い」にしない。[ADR-20261111-001][adr-keep-halt] の決定 1）。続けて、起動の前の確かめの順 1（合図が `run` で、全体の停止の Issue と見つかりの記録が無い）、順 2〜4（費用。`logic/session/budget.ts` で 1 枠を取り置くか、呼ぶ側が渡した取り置き済みの 1 枠を使う）、順 7（欄に入れる文の検疫と、ファイルの一覧の確かめ）、順 8（渡す文のハッシュ）を、この順に確かめる | — | `not-started`（外れた順と扱いを添える）。取り置いた枠を返す。フォルダはまだ作っていない |
| 2. 一時フォルダの確かめ | 短い一時フォルダの根（`sessionTmp.root`）が無ければ、権限 700 で作る。ID を決め、起動の前の確かめの順 5（根の持ち主・リンクでない・権限）と順 6（`<根>/<ID>` がまだ無く、`<根>/<ID>/claude-<uid>` の長さが上限の内）を確かめる | — | `not-started`（順 5・6。扱いは実行を終える） |
| 3. フォルダを作る | 同じ名前のセッションのフォルダがあれば、残りを探し方 2 で探し（`flow/session/stop.ts`）、残りが無ければ、ID のファイルから引いた短い一時フォルダ、セッションのフォルダの順に消す。セッションのフォルダを作り、一時フォルダの行と ID のファイル（`short-tmp-id.txt`）を書いてから、短い一時フォルダ（`<根>/<ID>`）を権限 700 で作り、実体のパスに解く | 一時フォルダの行 | 残りが見つかるか探し切れなければ、消さずに `not-stopped`（起動していないので、取り置いた枠を返し、終わりの行を書かない）。作れなければ `prepare-failed` |
| 4. 準備 | clone と worktree（受付 AI は作らない）、`canon/`、`tmp/` を作り、安全設定を組み立ててファイルに書き、中身のハッシュを持つ（「[AI のセッション][b03]」の「セッションごとの安全設定」の作り方の順 1・2） | — | `prepare-failed`（セッションの順 10（片付け）をしてから返す） |
| 5. 作業場所の確かめ | 起動の前の確かめの順 9（`.claude/settings.local.json` と `CLAUDE.local.md`） | — | `not-started`（セッションの順 10（片付け）をしてから返す） |
| 6. 起動 | 安全設定のファイルを読み直してハッシュを比べる（作り方の順 3）。入力を組み立て（欄の区切りの乱数はここで作る）、始まりの行を書き、`io/claude.ts` で起こし、標準入力に入力を書いて閉じ、プロセスの行を書く。`RunContext` の動いているセッションに足す | 始まりの行（安全設定のハッシュ、起動の時刻、`--max-budget-usd` の値、止める猶予）、プロセスの行（PID・PGID・起動の時刻・マシンの起動の時刻・ホスト名。ホスト名は `io/os.ts` の「ホスト名」で取る） | ハッシュが違えば、起動せずに `settings-tampered`（セッションの順 10（片付け）をしてから返す。人が確かめる材料として、セッションの名前と、作ったときと読み直したときの 2 つのハッシュを `RunContext` の「安全設定を書き換えられたセッション」に足し（役を問わない。`runs.jsonl` に残る。「[1 回の実行の流れ][d08]」の「1 回の実行の中で持つ値」）、2 つのハッシュを添えて返す。安全設定のファイルは、次の実行の最初の片付けが `sandbox-settings/` の残りを消すので残さない。「[AI のセッション][b03]」の「前の実行が残したセッション」の順 5） |
| 7. 見張り | 下の「見張り」（1 秒ごとの子孫のプロセスグループの控えを含む） | `stream-json` の行（`streams/`） | — |
| 8. 終わり | 止めたときは `flow/session/stop.ts` の止める手順。止めずに終わったときも、控えたプロセスグループ（探し方 1）と探し方 2 で残りを探す | — | 残りを止められなければ `not-stopped` |
| 9. 数える | 安全設定のファイルのハッシュをもう一度比べる（作り方の順 5）。`logic/session/budget.ts` で費用とトークンを数える。ハッシュが同じで、残りが無く、`result` があれば、出力契約を取り出して確かめる（「[文の検査と受け入れ][d06]」の「出力契約」）。役が点検の試しのときは、終わりの行を書く前に、呼ぶ側が渡した関数（終わり方の記号と `stream-json` の記録を受け、試しの結果と省く条件の値を返す）を呼び、返った値を終わりの行に入れる（`not-stopped` のときは、終わりの行を書かないので呼ばない。「[点検][d04]」の「試しのセッションの判定」）。終わりの行を書き、取り置いた枠を数えた費用に入れ替え、`RunContext` の動いているセッションから外す | 終わりの行（終わった後の安全設定のハッシュを含む）、出力契約（`outputs/`） | ハッシュが違えば `settings-tampered`（結果を使わない。順 6 と同じく、2 つのハッシュを `RunContext` に足す）。`not-stopped` のときは、表の下の箇条のとおり |
| 10. 片付け | 安全設定のファイルを消す。受付 AI のセッションは、短い一時フォルダ、セッションのフォルダの順に消す（「[AI のセッション][b03]」の「短い一時フォルダ」の順 5） | — | `not-stopped` のときは片付けない |

- `flow/session/run.ts` が受け取る値は、`RunContext`（費用の帳簿・動いているセッション・全体の止める合図と全体の停止の Issue の値。「[1 回の実行の流れ][d08]」の「1 回の実行の中で持つ値」）、セッションの指定（役・工程・セッションの名前・入れる欄・モデル）、取り置き済みの 1 枠（重い工程のときだけ。下の「費用の取り置き」）、終わりの行に足す値を決める関数（点検の試しのときだけ）。返す値は、終わり方の記号と、出力契約（`done` のとき）か、外れた順と扱い（`not-started` のとき）か、数えた値と残ったプロセス（`not-stopped` のとき。セッションの順 3 の `not-stopped` は数えた値を持たない）か、2 つのハッシュ（`settings-tampered` のとき。作ったときと、起動の直前かセッションの後に読み直したとき）。渡された関数を呼んだとき（点検の試しで、セッションの順 9 で終わりの行を書くとき。終わり方を問わない。`not-stopped` は終わりの行を書かないので呼ばない）は、関数が返した値も添える
- `RunContext` の動いているセッションには、セッションの順 6（起動）で足し、セッションの順 9（数える）で終わりの行を書いたときに外す。全体の停止の Issue を開いたとき（「[1 回の実行の流れ][d08]」の「全体の停止と通知」）と、思わない失敗で止まったときに、止めるセッションを見落とさないため
- 本箇条は、起動した後（セッションの順 8）の `not-stopped` の扱い。セッションの順 3 の `not-stopped` は、起動していないので、取り置いた枠を返し、終わりの行も停止中にした後の終わりの行も書かない。次の実行の全体の探し方は、同じ名前のセッションのフォルダの残りを、同じ名前の前のセッションの終わりの行で分ける（「[AI のセッション][b03]」の「前の実行が残したセッション」の順 3 と表の下。人に渡したかが分からなければ点検の fail）。セッションの順 8（終わり）で残りを止められなければ（`not-stopped`）、セッションの順 9（数える）で費用とトークンと終わった後のハッシュを数えるが、終わりの行を書かず、取り置いた枠も `RunContext` の動いているセッションも外さず、数えた値と残ったプロセス（PID・コマンドの名前・フォルダ）を添えて返す。セッションの順 10（片付け）もしない。終わりの行は、停止中にした後に書く（「[AI のセッション][b03]」の「止める手順」の順 5、[ADR-20261022-004][adr-intake-req] の決定 2）。作業の単位のセッションは、`flow/steps/stop.ts` が `session-not-stopped` の `stop` の印を止めた先のすべて（Issue と、PR のセッションなら PR）に書けた後に、`flow/session/leftovers.ts` の停止中にした後の終わりの行を書く処理で、数えた費用と、`session-not-stopped` で人に渡したことを書き、取り置いた枠を数えた費用に入れ替えて、動いているセッションから外す。`stop` の印を書けなかったとき（合図が `run` でない、GitHub が断る、時間の上限を過ぎた）は、終わりの行を書かない。次の実行が「前の実行が残したセッション」でもう一度見つけ、停止中にし直す。作業の単位を持たないセッション（受け入れの依頼の実行のセッションと、点検の試しのセッション）は、終わりの行を書かない。人が残りを止めた後の実行が、前の実行が残したセッションとして探し直し、残りが無いと確かめてから書く

| 先後 | 終わり方の記号 | 中身 |
| --- | --- | --- |
| 1 | `not-stopped` | 残ったコマンドを止められなかった（セッションの順 8）か、作り直す前に残りが見つかったか探し切れなかった（セッションの順 3）。扱いは停止中（`session-not-stopped`） |
| 2 | `settings-tampered` | 安全設定のファイルのハッシュが、起動の直前（セッションの順 6）かセッションの後（セッションの順 9）に、作ったときと違った。起動の直前なら起動せず、後なら結果（出力契約）を使わない |
| 3 | `stop-signal` | 全体の止める合図が `run` でなくなったか、全体の停止の Issue を開いた（`flow/safety/halt.ts`）ので止めた（実行の失敗に数えない） |
| 4 | `limit-time`・`limit-turns`・`limit-cost` | 時間・ターン・費用の上限に当たった（`result` の文が JSON として読めても、こちらを返す。「[AI のセッション][b03]」の「レビューの軸の起こし方」の 5 つの条件の (1)） |
| 5 | `refusal` | 拒否で止まった（`stream-json` のどれかの行の `stop_reason` が `refusal`。「[文の検査と受け入れ][d06]」の「出力契約」）。`is_error` が真でも、こちらを返す |
| 6 | `error` | `is_error` が真か、`claude` が `result` を出さずに終わった |
| 7 | `contract-invalid` | 終わったが、出力契約を取り出せないか、確かめに外れた |
| 8 | `done` | `result` があり、出力契約を取り出せた |
| — | `not-started` | 起動の前の確かめに外れた（外れた順と扱いを添える）。扱いは `deferred`・`stopped`・`suspected`・実行を終えるのどれか。実行を終えるときは、理由の記号を添える：起動の前の確かめの順 1 の合図が `run` でないときは `stop-signal`、読めないときは `signal-unreadable`、順 5・6 と、順 9 の上のフォルダのときは `machine-unsafe`。順 1 で全体の停止の Issue（見つかりの記録があるときを含む）に当たったときは `deferred`（実行を終えない。AI を使わない工程は続ける） |
| — | `prepare-failed` | セッションの順 3・4 の準備（フォルダ、clone、worktree、`canon/`、安全設定のファイル）が失敗したか、子プロセスの時間の上限を過ぎた（実行の失敗） |

- 起動した後に 2 つ以上が当てはまるときは、先後の小さい記号を返す。`not-started` と `prepare-failed` は、起動の前だけに起きる。`not-stopped` と `settings-tampered` は、起動の前（セッションの順 3・6）にも起きる
- 終わり方の記号は、どの役のセッションも同じ一覧を使う。役ごとの扱い（受付 AI の拒否は次の回のモデルを変える、など）は、呼ぶ側の工程が決める。1 つの工程が 2 つ以上のセッションを起こしたとき（計画の輪、レビューのラウンド）は、工程のファイルが、セッションごとの記号を上の先後で 1 つにしてから、工程の結果に写す（写し方は「[1 回の実行の流れ][d08]」の「工程の結果」）

## 費用の取り置き

費用の帳簿は、`RunContext` が持つ 1 つの値（「[1 回の実行の流れ][d08]」の「1 回の実行の中で持つ値」）で、今日の累計・今の実行の累計・作業の単位ごとの累計と、取り置き（枠ごと）からなる。`logic/session/budget.ts` は、帳簿の型と、取り置く・枠を使う・使わなかった枠を返す・数えた費用に入れ替える関数を持ち、どれも帳簿を受け取って新しい帳簿を返す。

- 起動の前（セッションの順 1）に、起動するセッションの費用の上限（`limits.session.costUsd`）の分を、1 枠として取り置く。取り置けるのは、累計と取り置き済みの枠と新しい枠を足しても、1 日・1 回の実行・作業の単位の上限を超えないときだけ（「[AI のセッション][b03]」の「起動の前の確かめ」の順 2〜4）
- 重い工程は、工程を始める前に、工程が起こしうるセッションの数の分をまとめて取り置き（計画の工程は `3 + 2 × limits.planRevisions`、レビューの 1 ラウンドは 5）、枠の並び（札）を受け取る。工程は、セッションを起こすたびに 1 枠を `flow/session/run.ts` に渡す。渡されたときは、セッションの順 1 で新しく取り置かず、その枠を使う。取り置いた枠は取り置き済みの枠に入っているので、使う枠を起動するセッションとしてもう一度足さない（順 2〜4 は、工程の前のまとめた比べで決まっている）。工程が早く終わったら、使わなかった枠を返す
- セッションが終わったら（終わりの行を書いたら）、枠を外し、数えた費用（途中で止めた回は `--max-budget-usd` の値）を累計に入れる。`not-stopped` のセッションの枠は、停止中にした後の終わりの行を書くまで外さない
- 流れの層は、`RunContext` の帳簿を読んでから入れ替えるまでの間に待ち（`await`）をはさまない。3 つの軸を同時に動かしても、ほかのセッションの取り置きを上書きしないため
- 帳簿は、進行 Bot の 1 つのプロセスの中にだけ持つ。実行の lock で、同じマシンで同じリポの実行は 1 つだけなので、ファイルで守る要は無い。帳簿の最初の値は、手元の記録の `sessions.jsonl` の終わりの行と、終わりの行の無いセッションの始まりの行から作る
- レビューのラウンドは重い工程なので、`flow/steps/review.ts` がラウンドの前に 5 つ分をまとめて取り置き、3 つの軸には 1 枠ずつ渡して起こす。3 つの軸の分を 1 つずつ取り置かないので、2 つ目までを起こした後に 3 つ目を起こせずにラウンドを捨てることは無い（基本設計の「同時に起こすセッションは 3 つ分をまとめて足して比べる」は、5 つ分のまとめた比べに入る）

## 入力の欄の区切り

`logic/session/input.ts` は、固定の指示文と、区切った欄を、標準入力に渡す 1 つの文にする（「[AI のセッション][b03]」の「渡し方の決まり」）。

- 欄の始まりの行は `<<<DAP-FIELD name=<欄の名前> source=<出どころ> id=<乱数>>>>`、終わりの行は `<<<DAP-END id=<乱数>>>>` にする。乱数は、渡すセッションごとに起動の直前に作る 16 バイトを 16 進で書いたもの。欄の名前と出どころは、決まった値の一覧から選ぶ
- 決まった部分（`<<<DAP-FIELD` と `<<<DAP-END`）の見つけ方は、本ファイルの定数に 1 つだけ持ち、検疫もこれを使う（「[文の検査と受け入れ][d06]」の「検疫」の `delimiter`）。見つけ方は、`<<<` の後に空白（空白・タブ）を 0 個以上はさみ、`DAP`、空白を 0 個以上、`-`、空白を 0 個以上、`FIELD` か `END` が続くもの（英字の大小を問わない）。後ろの `>>>` と乱数の部分は見つけ方に入れない（`>>>` は Python の対話の例や衝突の印に普通に現れるため）。欄に入れる文に決まった部分があれば、起動の前の確かめの順 7（欄に入れる文の検疫）で起動しない
- 欄に入れる AI と人の文と、PR の差分（人の push を含む）は、`QuarantinedText` でだけ受け取る（「[文の検査と受け入れ][d06]」の「検査を通った文の型」）。漏えいの検査は掛けない（漏えいの検査は GitHub に書く文に掛ける。[IMPL-15][impl]）
- 機械で付けた事実（CI の結果、ファイルの一覧、SHA）は、決まった形の値として受け取る。ファイルの名前は作業 AI が付けられるので、ファイルの一覧（変更ファイルと衝突したファイル）は、起動の前の確かめの順 7 で検疫と一緒に、改行などの制御文字と区切りの決まった部分が無いことを確かめる。外れたら、PR の差分で見つかったときと同じく攻撃の疑い（`where` が `code`）にする（種類の記号は、区切りの決まった部分なら `delimiter`、制御文字なら `invisible`）。ファイルの名前は次の実行でも同じなので、実行の失敗にすると `retry-limit` まで同じ外れを繰り返すため

## 見張り

セッションの順 7（見張り）は、次を同時に見張る。1 秒ごとの子孫の行のほかは、最初に当たったもので終わる。

| 見張るもの | 当たったとき |
| --- | --- |
| `io/claude.ts` が渡す `stream-json` の行 | 行を記録に足し、`result` の行を受けたら、`claude` が終わるのを待つ |
| 起動からの時間（`FlowSystem` の `now` で数える） | `limits.session.minutes` を過ぎたら、止める手順（`limit-time`） |
| 全体の止める合図（`run.stopSignalPollSeconds` ごとに `flow/safety/signal.ts` で読む） | 返す 3 つの値で分ける。`run` なら続ける。ほかの値なら、止める手順（`stop-signal`）。読めないときは、止めずに見張りを続け、次の回にもう一度読む（[ADR-20261017-007][adr-stop] の決定 2） |
| 1 秒ごとの `claude` の子孫（`io/processes.ts` でプロセスの一覧を読む） | 終わらない。`logic/session/stop-targets.ts` で、子孫のプロセスグループを控えに足し、プロセスが 1 つも無くなったものを控えから外す（足し方と外し方は「[AI のセッション][b03]」の「止める手順」の順 1）。控えは、セッションの順 8（終わり）の探し方 1 に渡す |
| `claude` のプロセスが終わったこと | セッションの順 8（終わり）へ |

- 合図を読めないときに止めないのは、承認済みの [ADR-20261017-007][adr-stop] の決定 2（間の読み取りの失敗では止めない）のため。セッションが終わった後に GitHub に書く前に、`flow/run/write.ts` がもう一度合図を読み、読めなければ書かないので、読めない間に人が `stop` にしても、書き込みは止まる。1 回の読みが時間の上限（`run.commandMinutes`）を過ぎたときも、読めなかったとして続ける。読みが終わるか取り消されるまで、次の読みを始めない
- 待つことは `FlowSystem` の `sleep` で行い、タイマーを入口の層の外で直接使わない（[README][readme] の「構成の検査に足すこと」）

## 止める相手と前の実行の残り

`logic/session/stop-targets.ts` は、プロセスの一覧（PID・親・PGID・起動の時刻）と、セッションの起動の時刻と、探し方 1 と 2 で見つけたプロセスを受け取り、`SIGKILL` を送るプロセスグループの一覧と、止めなかったプロセスの一覧を返す（「[AI のセッション][b03]」の「止める手順」の「止める相手」）。控えの更新（プロセスの一覧と今の控えから、新しい控えを返す）も受け持つ。

- 親をたどる途中で、プロセスの一覧に親が無い（読む間に終わった）ときは、止める相手にしない。誤って人のプロセスを止めるより、残ったものとして人に渡す側に倒す
- 起動の時刻は秒の単位のエポック秒で比べ、同じ秒に生まれたプロセスは、起動の時刻以後とする（「[外との境][d01]」の「OS ごとの部分」のプロセスの起動の時刻）
- 探し方 2（`flow/session/stop.ts`）は、探すフォルダ（セッションのフォルダ、短い一時フォルダ、前の実行が残したセッションの順 3 の置き場の `sessions/` と短い一時フォルダの根）ごとに、先に `io/files.ts` の `lstat` で確かめる。無い（`ENOENT`）フォルダは `lsof +D` に渡さず、そのフォルダでは「見つからなかった」とする。無いフォルダを `lsof +D` に渡すと、終了コード 1 で標準エラーに文が出て、探し切れなかったになるため（[FACT-115][facts]）。無いフォルダの中を作業フォルダにしていたプロセスは、`lsof +D` でも見つけられないので、外しても見つけられるものは減らない。フォルダでない（シンボリックリンクかファイル）か、`lstat` がほかの失敗を返したら、探し切れなかったとする（止める側）
- `io/processes.ts` の探し方 2 の結果は、見つけた・見つからなかった・探し切れなかったの 3 つ（「[外との境][d01]」の「プロセスの一覧と開いているファイル」）。探し切れなかったときは、見つけたときと同じく、残りを止められなかったとして扱う

`logic/session/leftovers.ts` は、`sessions.jsonl` の行から、始まりの行があって終わりの行の無いセッションを並べ、セッションごとに探し方 1 を使ってよいか（プロセスの行があり、マシンの起動の時刻が今と同じで、プロセスグループの先頭のプロセスの起動の時刻が記録と同じか、先頭が無い）を返す（「[AI のセッション][b03]」の「前の実行が残したセッション」の表の下）。

## レビューのラウンド

`flow/session/review-round.ts` は、「[AI のセッション][b03]」の「レビューの軸の起こし方」の順に、次のとおり進める。

1. 3 つの軸を並べて起こし、3 つすべての終わりを待つ
2. 3 つの軸に 5 つの条件を掛ける。1 つでも満たさなければ、見落としの軸を起こさずにラウンドを捨てる（見落としの軸に渡す 3 つの軸の指摘が分からないため）
3. 満たせば見落としの軸を起こし、終わったら 5 つの条件を掛ける。満たさなければラウンドを捨てる
4. 4 つの軸の 🔴 🟡 を数え、1 件以上なら批評 AI を起こし、5 つの条件を掛ける。0 件なら批評 AI を起こさない

- 3 つの軸は、`flow/steps/review.ts` がラウンドの前に取り置いて渡した 5 つ分（上の「費用の取り置き」）から 1 枠ずつ渡して、`flow/session/run.ts` を 3 つ同時にセッションの順 1 から動かし、3 つすべての終わりを待つ。1 つが早く失敗しても、ほかを止めずに終わりを待つ。動いているセッションを残して次の順に進まないため。起こさなかった軸と批評 AI の枠は、返り値で `flow/steps/review.ts` に知らせる（帳簿に返すのは `flow/steps/review.ts`）
- 上の 2〜4 で、条件を掛けたセッションが 1 つでも外れれば、ラウンドの結果を捨て、`review` の印を書かずに実行の失敗にする。次の実行は、3 つの軸から起こし直す
- 全体の止める合図か全体の停止の Issue で 1 つでも止めたら（`stop-signal`）、ほかの動いているセッションも止める手順で止め、ラウンドを捨てる（実行の失敗に数えない）
- `flow/session/review-round.ts` は、セッションごとの終わり方の記号の並びと、使わなかった枠と、5 つの条件を満たしたときは 4 つの軸（と批評 AI）の出力契約を返す。工程の結果（「[1 回の実行の流れ][d08]」の「工程の結果」）に写すのは `flow/steps/review.ts` で、記号の並びを上の「セッションの順」の終わり方の記号の先後で 1 つにしてから写す。条件を満たさなかったときは `failed` にする

| ファイル | 単体テストで確かめること |
| --- | --- |
| `logic/session/names.ts` | 工程ごとの名前と、名前から工程と番号を読み戻せること。読めない名前を残骸の見分けで「Issue や PR を引けない」と返すこと |
| `logic/session/env.ts`・`sandbox.ts`・`args.ts` | 決めた名前だけの環境変数、足せない名前を足したときに止めること。安全設定と引数の組み立て（基本設計の表の行ごと）。一覧の値の照らしは、「[設定と記録][d02]」の `logic/settings/fixed.ts` のテストが受け持つ |
| `logic/session/input.ts` | 欄の区切りに毎回違う乱数が入ること。`QuarantinedText` でない文を欄に入れると型の検査で落ちること。決まった部分の見つけ方が、空白と英字の大小の揺れに当たり、後ろの `>>>` だけに当たらないこと。`review` Skill の本文の置き換えと、置き換えずに残った書き方で止まること |
| `logic/session/preflight.ts` | 順 1〜9 の外れ方ごとの扱い。順 1 で、全体の停止の Issue があるとき（見つかりの記録があり、全体の停止の Issue を読み直して無いときを含む）に起動せず実行を終えない扱い（`deferred`）を、合図が `run` でないか読めないときに実行を終える扱いを、理由の記号つきで返すこと。順 5・6 と順 9 の上のフォルダで、実行を終える扱い（`machine-unsafe`）を返すこと。取り置きの結果を事実として受けて順 2〜4 を決めること。ファイルの一覧に区切りの決まった部分か制御文字があれば、順 7 の外れ（`where` が `code`）を返すこと |
| `logic/session/budget.ts` | まとめて取り置き、使わなかった枠を返すこと。渡された枠を使うときに、順 2〜4 を 2 回数えないこと。上限を超える取り置きを断ること。帳簿を受け取って新しい帳簿を返し、渡した帳簿を変えないこと。終わり方ごとの費用とトークンの数え方（`assistant` の `usage` を足さないこと） |
| `logic/session/conditions.ts` | 5 つの条件の外れ方ごとと、モデルの一致（別名と完全な ID） |
| `logic/session/stop-targets.ts` | 起動の時刻より前のプロセスを親に持つものを止めないこと。親が一覧に無いときに止めないこと。同じ秒に生まれたものを止めること。控えに子孫のプロセスグループを足し、プロセスが無くなったものを外すこと |
| `logic/session/leftovers.ts` | 終わりの行の無いセッションの並べ方。探し方 1 を使ってよい組み合わせ（マシンの起動の時刻、先頭のプロセスの有無と起動の時刻） |
| `flow/session/prepare.ts` | フォルダ・clone と worktree・短い一時フォルダ・安全設定のファイルを決まった順で作ること。一時フォルダの行と ID のファイルを、短い一時フォルダを作る前に書くこと。同じ名前のフォルダの残りが見つかれば消さないこと |
| `flow/session/run.ts` | セッションの順と、終わり方の記号ごとの記録。起動の前の確かめの順 6 が、短い一時フォルダを作る前に行われること。起動しなかったときに受付 AI のフォルダを残さないこと。起動の直前とセッションの後に安全設定のハッシュを比べ、違えば `settings-tampered` を返し、後で違ったときに出力契約を取り出さないこと。止めずに終わったときも残りを探すこと。残りを止められなければ、終わりの行を書かず、片付けず、動いているセッションから外さずに返すこと。起動で動いているセッションに足し、終わりの行を書いたときに外すこと。見張りの合図が読めないときに止めず、`run` でない値のときだけ止めること。時間の上限で止めて残りも止められないときに `not-stopped` を返すこと。上限に当たって `result` が JSON として読めるときに上限の記号を返すこと。点検の試しのセッションと受け入れの依頼の実行の受付 AI のとき、開き直しの条件に当たる作業の単位があれば、順 1 で `not-started`（`deferred`）を返すこと。定期の実行の下書きと書き直しの受付 AI では、作業の単位の Issue を読まないこと。渡された関数の値を終わりの行に入れ、関数の無い役では入れないこと。関数を呼んだときは、関数の値を返す値にも入れること。`not-stopped` と `not-started` では関数を呼ばないこと。セッションの順 3 で `not-stopped` を返すときに、取り置いた枠を返し、終わりの行を書かないこと。起動の直前の `settings-tampered` で、2 つのハッシュを返し、安全設定のファイルを消すこと。起動の直前とセッションの後の `settings-tampered` で、役を問わず、セッションの名前と 2 つのハッシュを `RunContext` に足すこと |
| `flow/session/stop.ts` | 止める手順の順 2〜5。`io/processes.ts` の 3 つの結果（見つけた・見つからなかった・探し切れなかった）ごとの扱い。無いフォルダを `lsof` に渡さず見つからなかったとすること。リンクかファイルなら探し切れなかったとすること |
| `flow/session/leftovers.ts` | 前の実行が残したセッションの片付けの順 1〜5。停止中にした後の終わりの行を、呼ばれたときだけ書くこと |
| `flow/session/review-round.ts` | 渡された 5 つ分の枠から、3 つの軸に 1 枠ずつ渡して同時に起こすこと。1 つが失敗しても終わりを待ってからラウンドを捨てること。3 つの軸のどれかが条件を満たさなければ見落としの軸を起こさないこと。条件を満たした後に 🔴 🟡 を数え、0 件なら批評 AI を起こさないこと。起こさなかった軸と批評 AI の枠を返り値で知らせ、帳簿を自分で入れ替えないこと |

- 偽の `claude` の筋書き（`SIGTERM` を無視するコマンドを裏に残す、返事をせずに待つ、など）で、止める手順と残りの探し方を結合テストで確かめる（「[テスト][b05]」の「偽物」）
