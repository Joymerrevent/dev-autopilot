# AI のセッション

AI のセッションを準備し、起こし、見張り、止め、費用を数える処理の作りを決める。
起動の形・環境変数・短い一時フォルダ・安全設定・上限・起動の前の確かめ・止める手順・前の実行が残したセッション・費用の数え方・レビューの軸の起こし方の正本は、基本設計の「[AI のセッション][b03]」にある。本書は、正本を並べ直さず、ファイルの分け方、1 つのセッションの段階と終わり方、費用の取り置き、入力の欄の区切りの形を決める。

## ファイルの一覧

| ファイル | 層 | 受け持つこと | 基本設計 |
| --- | --- | --- | --- |
| `logic/session/names.ts` | 判断 | セッションの名前の組み立てと、名前から工程と Issue か PR の番号を読む処理（作業場所の残骸の見分けと共有） | 「[AI のセッション][b03]」の「セッションの名前」 |
| `logic/session/env.ts` | 判断 | 子プロセスに渡す環境変数の組み立てと、足せない名前の一覧 | 同上の「環境変数」 |
| `logic/session/sandbox.ts` | 判断 | セッションごとの安全設定の組み立て | 同上の「セッションごとの安全設定」 |
| `logic/session/args.ts` | 判断 | `claude` の引数の組み立て | 同上の「起動の形」 |
| `logic/session/input.ts` | 判断 | 固定の指示文と区切った欄を、標準入力に渡す 1 つの文にする。`review` Skill の本文の置き換えと確かめ | 同上の「役ごとの入力」「レビューの軸の起こし方」 |
| `logic/session/preflight.ts` | 判断 | 起動の前の確かめ（順 1〜9）の判定。呼ぶ側が集めた事実から、起動するか、外れたときの扱いを返す | 同上の「起動の前の確かめ」 |
| `logic/session/budget.ts` | 判断 | 費用の取り置き（下の「費用の取り置き」）と、`stream-json` からの費用とトークンの数え方 | 同上の「上限」「費用の数え方」 |
| `logic/session/conditions.ts` | 判断 | レビューの 5 つの条件（[IMPL-18][impl]）と、モデルの一致の判定 | 同上の「レビューの軸の起こし方」 |
| `logic/session/stop-targets.ts` | 判断 | プロセスの一覧から、止める相手のプロセスグループを決める | 同上の「止める手順」 |
| `logic/session/leftovers.ts` | 判断 | 手元の記録から、前の実行が残したセッションと、探し方 1 を使ってよいかを決める | 同上の「前の実行が残したセッション」 |
| `flow/session/prepare.ts` | 流れ | セッションのフォルダ、clone と worktree、短い一時フォルダ、安全設定のファイルを作る | 同上の「セッションの名前」「短い一時フォルダ」「セッションごとの安全設定」 |
| `flow/session/run.ts` | 流れ | 1 つのセッションを、下の「段階」のとおりに動かす | 同上の「起動の形」「止め方と利用枠の数え方」 |
| `flow/session/stop.ts` | 流れ | 止める手順と、残りの探し方 | 同上の「止める手順」 |
| `flow/session/leftovers.ts` | 流れ | 前の実行が残したセッションの片付け | 同上の「前の実行が残したセッション」 |
| `flow/session/review-round.ts` | 流れ | レビューの 1 ラウンド（3 つの軸を並べて起こし、見落としの軸、批評 AI） | 同上の「レビューの軸の起こし方」 |

- `claude` を起こし `stream-json` を 1 行ずつ渡すのは外との境の `io/claude.ts`、プロセスの一覧と開いているファイルを読むのは `io/processes.ts`（「[外との境][d01]」）
- 判断の層のファイルは、時刻・プロセス・ファイルの情報を引数で受ける。止める相手の見分けと探し方 1 の判定のように、誤ると人のプロセスを止めうる処理を、単体テストで組み合わせごとに確かめられるようにするため

## 段階

![1 つのセッションの段階][fig-lifecycle]

`flow/session/run.ts` は、1 つのセッションを次の段階で動かし、終わり方の記号を返す。流れの層の工程は、終わり方の記号で扱いを決める（実行の失敗にするか、停止中にするか、次の工程へ進むか）。

| 段階 | すること | 記録（`sessions.jsonl`。「[設定と記録][d02]」の「手元の記録」） |
| --- | --- | --- |
| 1. 一時フォルダ | 短い一時フォルダの ID を決め、行を書いてから作る | 一時フォルダの行 |
| 2. 準備 | `flow/session/prepare.ts` で、セッションのフォルダ・clone・worktree・安全設定のファイルを作る | — |
| 3. 起動の前の確かめ | 事実を集めて `logic/session/preflight.ts` に渡し、外れたら起動しない | — |
| 4. 費用の取り置き | 下の「費用の取り置き」 | — |
| 5. 起動 | `io/claude.ts` で起こし、標準入力に入力を書いて閉じる | 始まりの行（起動の時刻、`--max-budget-usd` の値、止める猶予）、プロセスの行（PID・PGID・起動の時刻・マシンの起動の時刻・ホスト名） |
| 6. 見張り | 下の「見張り」 | `stream-json` の行（`streams/`） |
| 7. 終わり | 止めたときは `flow/session/stop.ts` の止める手順。止めずに終わったときも残りを探す | — |
| 8. 数える | `logic/session/budget.ts` で費用とトークンを数え、取り置きを実際の費用に入れ替える。出力契約を取り出して確かめる（「[文の検査と受け入れ][d06]」の「出力契約」） | 終わりの行、出力契約（`outputs/`） |
| 9. 片付け | 受付 AI のセッションは、残りが無いと確かめた後に短い一時フォルダとセッションのフォルダを消す。安全設定のファイルを消す | — |

| 終わり方の記号 | 中身 |
| --- | --- |
| `done` | `result` があり、出力契約を取り出せた |
| `contract-invalid` | 終わったが、出力契約を取り出せないか、確かめに外れた |
| `limit-time`・`limit-turns`・`limit-cost` | 時間・ターン・費用の上限に当たった |
| `stop-signal` | 全体の止める合図で止めた（実行の失敗に数えない） |
| `refusal` | 拒否で止まった（`stop_reason` が `refusal`） |
| `error` | `is_error` が真か、`claude` が `result` を出さずに終わった |
| `not-started` | 起動の前の確かめに外れた（外れた順と扱いを添える） |
| `not-stopped` | 残ったコマンドを止められなかった（`session-not-stopped`） |

- 終わり方の記号は、どの役のセッションも同じ一覧を使う。役ごとの扱い（受付 AI の拒否は次の回のモデルを変える、など）は、呼ぶ側の工程が決める
- 段階 7 で残りを止められなければ、段階 8 の費用は数えるが、段階 9 の片付けをせず、終わりの行に人に渡したことを書く（「[AI のセッション][b03]」の「止める手順」の順 5）

## 費用の取り置き

`logic/session/budget.ts` は、1 回の実行の中の費用の帳簿を持つ。帳簿は、今日の累計・今の実行の累計・作業の単位ごとの累計と、動いているセッションの取り置きからなる。

- 起動の前に、起動するセッションの費用の上限（`limits.session.costUsd`）の分を取り置く。取り置けるのは、累計と動いているセッションの取り置きと、新しい取り置きを足しても、1 日・1 回の実行・作業の単位の上限を超えないときだけ（「[AI のセッション][b03]」の「起動の前の確かめ」の順 2〜4）
- 重い工程は、工程を始める前に、工程が起こしうるセッションの数の分をまとめて取り置き、セッションを起こすたびに 1 つ分ずつ使う（計画の工程は `3 + 2 × limits.planRevisions`、レビューの 1 ラウンドは 5）。工程が早く終わったら、使わなかった分を返す
- セッションが終わったら、取り置きを外し、数えた費用（途中で止めた回は `--max-budget-usd` の値）を累計に入れる
- 帳簿は、進行 Bot の 1 つのプロセスの中にだけ持つ。実行の lock で、同じマシンで同じリポの実行は 1 つだけなので、ファイルで守る要は無い。帳簿の最初の値は、手元の記録の `sessions.jsonl` の終わりの行と、終わりの行の無いセッションの始まりの行から作る
- 並べて起こす 3 つの軸は、3 つ分をまとめて取り置いてから起こす。1 つずつ取り置くと、2 つ目までを起こした後に 3 つ目を起こせず、ラウンドを捨てることになるため

## 入力の欄の区切り

`logic/session/input.ts` は、固定の指示文と、区切った欄を、標準入力に渡す 1 つの文にする（「[AI のセッション][b03]」の「渡し方の決まり」）。

- 欄の始まりの行は `<<<DAP-FIELD name=<欄の名前> source=<出どころ> id=<乱数>>>>`、終わりの行は `<<<DAP-END id=<乱数>>>>` にする。乱数は、渡すセッションごとに起動の直前に作る 16 バイトを 16 進で書いたもの。欄の名前と出どころは、決まった値の一覧から選ぶ
- 決まった部分（`<<<DAP-FIELD` と `<<<DAP-END`。英字の大小と空白の揺れを問わない）は、検疫が欄の区切りを模した文字列として探す（「[文の検査と受け入れ][d06]」の「検疫」の `delimiter`）。欄に入れる文に決まった部分があれば、起動の前の確かめの順 7 で起動しない
- 欄に入れる AI と人の文は、`CheckedText` でだけ受け取る（「[文の検査と受け入れ][d06]」の「検査を通った文の型」）。機械で付けた事実（CI の結果、ファイルの一覧、SHA）は、決まった形の値として受け取り、欄に書く前に改行と区切りの決まった部分が無いことを確かめる。ファイルの名前は作業 AI が付けられるので、ファイルの一覧も確かめる

## 見張り

段階 6 は、次を同時に見張り、最初に当たったもので終わる。

| 見張るもの | 当たったとき |
| --- | --- |
| `io/claude.ts` が渡す `stream-json` の行 | 行を記録に足し、`result` の行を受けたら、`claude` が終わるのを待つ |
| 起動からの時間（システムの `now` で数える） | `limits.session.minutes` を過ぎたら、止める手順（`limit-time`） |
| 全体の止める合図（`run.stopSignalPollSeconds` ごとに GitHub の API で読む） | `run` でなくなったら、止める手順（`stop-signal`）。読めなかったときは、読めないまま次の回まで待ち、続けて読めない時間が `run.commandMinutes` を過ぎたら止める |
| `claude` のプロセスが終わったこと | 段階 7 へ |

- 合図を読めないときにすぐ止めないのは、一時のつながりの失敗で、動いているセッションを捨てないため。読めない時間が子プロセスの時間の上限と同じ長さを過ぎたら、止める側に倒す
- 待つことはシステムの `sleep` で行い、タイマーを入口の層の外で直接使わない（[README][readme] の「構成の検査に足すこと」）

## 止める相手と前の実行の残り

`logic/session/stop-targets.ts` は、プロセスの一覧（PID・親・PGID・起動の時刻）と、セッションの起動の時刻と、探し方 1 と 2 で見つけたプロセスを受け取り、`SIGKILL` を送るプロセスグループの一覧と、止めなかったプロセスの一覧を返す（「[AI のセッション][b03]」の「止める手順」の「止める相手」）。

- 親をたどる途中で、プロセスの一覧に親が無い（読む間に終わった）ときは、止める相手にしない。誤って人のプロセスを止めるより、残ったものとして人に渡す側に倒す
- 起動の時刻は秒の単位のエポック秒で比べ、同じ秒に生まれたプロセスは、起動の時刻以後とする（「[外との境][d01]」の「OS ごとの部分」のプロセスの起動の時刻）

`logic/session/leftovers.ts` は、`sessions.jsonl` の行から、始まりの行があって終わりの行の無いセッションを並べ、セッションごとに探し方 1 を使ってよいか（プロセスの行があり、マシンの起動の時刻が今と同じで、プロセスグループの先頭のプロセスの起動の時刻が記録と同じか、先頭が無い）を返す（「[AI のセッション][b03]」の「前の実行が残したセッション」の表の下）。

## レビューのラウンド

`flow/session/review-round.ts` は、「[AI のセッション][b03]」の「レビューの軸の起こし方」の順に、3 つの軸を並べて起こし、3 つが終わってから見落としの軸、4 つの軸の 🔴 🟡 が 1 件以上なら批評 AI を起こす。

- 3 つの軸は、上の「費用の取り置き」でまとめて取り置いてから、`flow/session/run.ts` を 3 つ同時に動かし、3 つすべての終わりを待つ。1 つが早く失敗しても、ほかを止めずに終わりを待つ。動いているセッションを残して次の段階に進まないため
- 4 つの軸と批評 AI の結果に、`logic/session/conditions.ts` で 5 つの条件を掛ける。1 つでも外れれば、ラウンドの結果を捨て、`review` の印を書かずに実行の失敗にする。次の実行は、3 つの軸から起こし直す
- 全体の止める合図で 1 つでも止めたら、ほかの動いているセッションも止める手順で止め、ラウンドを捨てる（実行の失敗に数えない）

## テスト

| ファイル | 単体テストで確かめること |
| --- | --- |
| `logic/session/names.ts` | 工程ごとの名前と、名前から工程と番号を読み戻せること。読めない名前を残骸の見分けで「Issue や PR を引けない」と返すこと |
| `logic/session/env.ts`・`sandbox.ts`・`args.ts` | 決めた名前だけの環境変数、足せない名前を足したときに止めること。安全設定と引数の組み立て（基本設計の表の行ごと） |
| `logic/session/input.ts` | 欄の区切りに毎回違う乱数が入ること。`CheckedText` でない文を欄に入れると型の検査で落ちること。ファイルの一覧に区切りの決まった部分か改行があれば組み立てないこと。`review` Skill の本文の置き換えと、置き換えずに残った書き方で止まること |
| `logic/session/preflight.ts` | 順 1〜9 の外れ方ごとの扱い |
| `logic/session/budget.ts` | まとめて取り置き、使わなかった分を返すこと。上限を超える取り置きを断ること。終わり方ごとの費用とトークンの数え方（`assistant` の `usage` を足さないこと） |
| `logic/session/conditions.ts` | 5 つの条件の外れ方ごとと、モデルの一致（別名と完全な ID） |
| `logic/session/stop-targets.ts` | 起動の時刻より前のプロセスを親に持つものを止めないこと。親が一覧に無いときに止めないこと。同じ秒に生まれたものを止めること |
| `logic/session/leftovers.ts` | 終わりの行の無いセッションの並べ方。探し方 1 を使ってよい組み合わせ（マシンの起動の時刻、先頭のプロセスの有無と起動の時刻） |
| `flow/session/run.ts` | 段階の順と、終わり方の記号ごとの記録。止めずに終わったときも残りを探すこと。残りを止められなければ片付けないこと |
| `flow/session/review-round.ts` | 3 つの軸をまとめて取り置いて同時に起こすこと。1 つが失敗しても終わりを待ってからラウンドを捨てること。🔴 🟡 が 0 件なら批評 AI を起こさないこと |

- 偽の `claude` の筋書き（`SIGTERM` を無視するコマンドを裏に残す、返事をせずに待つ、など）で、止める手順と残りの探し方を結合テストで確かめる（「[テスト][b05]」の「偽物」）
